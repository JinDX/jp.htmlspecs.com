1. はじめに

この節は規範的ではない。

HID（Human Interface Device）は、人間から入力を受け取る、または人間に出力を提供する種類のデバイスである。また、導入手順を簡素化するために設計された、ホストとデバイス間の双方向通信の標準である HID プロトコルも指す。HID プロトコルは当初 USB デバイス向けに開発されたが、その後 Bluetooth を含む多くの別のプロトコル上にも実装されている。

ウェブプラットフォームは、すでに多くの HID デバイスからの入力をサポートしている。キーボード、ポインティングデバイス、ゲームパッドは、いずれも通常 HID プロトコルを使用して実装される。しかし、このサポートは、HID 入力を高水準の入力 API に変換するオペレーティングシステムの HID ドライバーに依存している。ホストの HID ドライバーが十分にサポートしていないデバイスには、ウェブページからアクセスできないことが多い。同様に、ホストの HID ドライバーがサポートしない大半のデバイスの出力にもアクセスできない。

関連する解説文書も参照されたい。

2. 想定する用途

この節は規範的ではない。

2.1. 特殊用途のデバイス

最も一般的な種類の HID 入力デバイスは、既存の高水準の入力 API を通じて、すでにウェブプラットフォームで十分にサポートされている。たとえば、マウス入力には PointerEvent を通じて、キーボード入力には KeyboardEvent を通じてアクセスできる。これらのデバイスからの入力はホストのネイティブ HID ドライバーを使用して処理され、通常、正しく動作させるためにデバイス固有のドライバーや設定を必要としない。WebHID は、このように高水準の入力 API ですでに十分にサポートされているデバイスを対象としていない。

一部の種類の HID デバイスでは、ウェブプラットフォームがデバイスの一部の機能をサポートする一方、他の機能へのアクセスを制限している。たとえば、[GAMEPAD] は大半のゲームコントローラーの入力機能をサポートするが、LED インジケーターや音声など、あまり一般的でない機能はサポートしない。こうした機能はホスト API でも十分にサポートされていないことが多く、ユーザーエージェント内にサポートを追加すると、著しく複雑になる可能性がある。WebHID は、高水準 API が提供する機能が不十分な場合に、アプリケーションに代替手段を提供する。

多くの HID デバイスは、どのウェブプラットフォーム API でもサポートされていない。HID 仕様には、仮想現実の操作機器、フライトシミュレーター、医療機器など、HID を通じてサポートできる多種多様なデバイスが記述されている。WebHID により、追加のドライバーやユーザーエージェントの変更なしに、これらのデバイスを使用できるようになる。

2.2. 試作、趣味、教育用のデバイス

HID は、デバイスを使用するホストごとにドライバーを用意する代わりに、ホストの汎用 HID ドライバーを利用できるため、試作や趣味の用途に適している。導入手順が簡単になることで、教育者も各ホストのシステム設定を変更することなく、教室の生徒たちにデバイスを配備しやすくなる。ウェブプラットフォームを通じて HID デバイスへのアクセスを提供すれば、とりわけ現在ホスト固有のアプリケーションのみでサポートされているデバイスについて、導入に必要な作業をさらに減らせる。

3. セキュリティとプライバシーに関する考慮事項

この節は規範的ではない。

3.1. デバイスへのアクセスの悪用

HID 周辺機器は、ユーザーの明示的な同意なしにページからアクセス可能にするべきでない強力な機能を公開する場合がある。たとえば、周辺環境の情報を収集できるセンサーを備えることがある。デバイスには、公開したり上書きしたりするべきでない私的情報が保存されている場合もある。多くのデバイスは、ファームウェアを更新する機能を公開する。通常、オペレーティングシステムはアプリケーションから HID デバイスへのアクセスを制限せず、そのアクセスが悪用されて、デバイスが損傷したり保存データが破損したりすることがある。

場合によっては、デバイスがウェブページからまったくアクセス可能にするべきでない機能を公開している。ベンダー ID と製品 ID で特定のデバイスを識別し、列挙時に非表示にすることで、そのデバイスをブロックできる。レポート記述子によってデバイス自身の機能を記述できるため、ベンダー ID と製品 ID を事前に知り得ない場合でも、この情報を使って特定の種類のデバイスをブロックできる。これは、HID 用途の値をレポート記述子内のコレクションについて調べることで実現できる。たとえば、最上位コレクションにキーボードのHID 用途を持つデバイスへのアクセスを拒否すれば、キーボードに類するデバイスへのアクセスを拒否できる。

悪用を緩和するため、ユーザーが明示的にアクセスを許可するまで、デバイスはページから利用できない。まずページがアクセスを要求しなければならず、利用可能なすべてのデバイスを表示する選択画面でユーザーがデバイスを選ぶと、アクセスが許可される。ページにアクセスが許可されると、デバイスが使用中であることを示すインジケーターが表示される。

3.2. デバイスへの攻撃

HID プロトコルはきわめて汎用的で、その汎用性を活用した多種多様なデバイスが設計されている。そのため、悪意あるページがデバイスへのアクセスを利用してデバイス自体を損傷させる方法は数多く考えられる。カスタム HID レポートを使用してファームウェア更新を送信できる HID 周辺機器は比較的一般的である。デバイス製造者は、ファームウェアのバイナリーが真正であることを検証するよう更新機構を慎重に設計しなければならず、デバイスのセキュリティを低下させるダウングレードも防ぐべきである。信頼できない更新により、デバイスに新しい機能を追加したり、まったく別の種類のデバイスを装わせたりできる可能性がある。

想定範囲外の入力が与えられると損傷するデバイスもある。たとえば、ページが無効な振動コマンドを送信すると、ゲームパッドの振動機能が損傷する可能性がある。

一般に、この種の攻撃はデバイス固有であり、API の水準では緩和できない。

3.3. ホストへの攻撃

悪意あるページがデバイスへのアクセスを獲得すると、場合によってはそのアクセスをホストへの攻撃に利用できる。主な懸念は、デバイスを使って信頼された入力イベントを生成できるかどうかである。これらのイベントはユーザーの意図を代弁するものとして扱われ、ウェブプラットフォームのより強力な機能へのアクセスに使用できる。

マウスやキーボードは通常 HID 周辺機器として実装され、信頼された入力を生成することもできる。HID キーボードやマウスには、一連の入力を保存して後で再生できるプログラム可能なマクロなどの高度な機能が含まれることがある。デバイス製造者は、悪意あるアプリが意図しない入力列でデバイスを再プログラムできないよう、こうした機能を慎重に設計しなければならない。また、ユーザーの明示的な同意なしにマクロの再生が開始されないよう保護しなければならない。

3.4. 緩和策

セキュリティとプライバシーのリスクを緩和するため、ユーザーエージェントにはデバイスへのアクセス要求を選択画面に基づく手順で実装することを推奨する。ページが HID デバイスへのアクセスを要求したとき、ユーザーエージェントはページがデバイスへのアクセスを求めていることをユーザーに知らせるダイアログを表示するべきである。そのダイアログには接続された HID デバイスの一覧を表示し、ページに公開するデバイスを選ぶようユーザーに求めるべきである。誤クリックの可能性を減らすため、一覧からデバイスを選ぶ操作と、選択を確定してダイアログを閉じる操作という、別々の二つの操作を要求するべきである。

6. HID インターフェイス 

[Exposed=(DedicatedWorker,ServiceWorker,Window), SecureContext]
interface HID : EventTarget {
    attribute EventHandler onconnect;
    attribute EventHandler ondisconnect;
    Promise<sequence<HIDDevice>> getDevices();
    [Exposed=Window] Promise<sequence<HIDDevice>> requestDevice(
        HIDDeviceRequestOptions options);
};

注: ユーザーエージェントの実装は、条件付きの公開を選択してもよい。対象は hid 属性であり、これを持つ Navigator の関連するグローバルオブジェクト、すなわち Navigator のものが ServiceWorkerGlobalScope である場合が該当する。たとえば、ブラウザー拡張のコンテキスト（[browserext]）が挙げられる。

HID のインスタンスは、次の表に記述された内部スロットを持つものとして作成される:

内部スロット 初期値 説明（非規範的）
[[devices]] 空の順序付き集合 次の順序付き集合（要素型: HIDDevice のインスタンス）。これらはHID インターフェイスのうち、現在システムで利用可能なものを表す。
onconnect 属性、 型:EventHandler
onconnect はイベントハンドラー IDL 属性であり、対象はconnect イベント型である。
ondisconnect 属性、 型:EventHandler
ondisconnect はイベントハンドラー IDL 属性であり、対象はdisconnect イベント型である。
次のHID インターフェイスがシステムで利用可能になったとき、以下の手順を実行する:
このHID インターフェイスは、HID プロトコルを通じてデバイスと通信するために使用できる論理インターフェイスである。各HID インターフェイスは、一つだけのレポート記述子を持ち、それがインターフェイスでサポートされるレポートの集合を記述する。一つの物理デバイスは、複数を公開してもよい。その公開対象はHID インターフェイスである。複数のHID インターフェイスを持つデバイスは、インターフェイスごとにこの手順を一度実行する。

たとえば、USB デバイスはインターフェイスの集まりとして実装され、それぞれがインターフェイスクラスを指定してもよい。デバイスに HID クラスを使用する USB インターフェイスが複数ある場合、各インターフェイスは別々のHID インターフェイスとして列挙される。

  1. device を HIDDevice とする。

  2. device.[[vendorId]] を、このインターフェイスを公開するデバイスのベンダー ID に設定する。

  3. device.[[productId]] を、このインターフェイスを公開するデバイスの製品 ID に設定する。

  4. device.[[productName]] を、このインターフェイスを公開するデバイスの製品名に設定する。

  5. device.[[collections]] を、レポート記述子の構文解析の結果に設定する。

  6. hid を次の呼び出し結果とする: device の関連するグローバルオブジェクトの Navigator オブジェクトの hid 取得子。ただし、これは device の関連するグローバルオブジェクトが Window オブジェクトの場合であり、それ以外では、device の関連するグローバルオブジェクトの WorkerNavigator オブジェクトの hid 取得子の呼び出し結果とする。

  7. 追加する: device を hid.[[devices]] に。

  8. ユーザーが以前、サイトによる device へのアクセスを requestDevice() の呼び出しの結果として許可している場合、グローバルタスクをキューに入れる。対象の関連するグローバルオブジェクトは hid のもので、HID デバイスタスクソースを使用する。タスクではイベントを発火する。イベント名は connect、対象は hid、使用するインターフェイスは HIDConnectionEvent で、その device 属性を device に初期化する。

次の操作、すなわちレポート記述子を構文解析するには、以下の手順を実行する:
通常システムは、レポート記述子の バイト列を各HID インターフェイスについて、デバイスの初回接続時に読み取り、値をシステムレジストリーにキャッシュする。レポート記述子を利用できなくても、各レポートの配置を再構築できる情報をシステムが提供している場合、ユーザーエージェントは別のアルゴリズムを使用してもよい。その場合、省略する構文解析の対象はレポート記述子である.

レポート記述子の形式は、[USBIF-HID-CLASS] の 6.2.2 節に記述されている。以下のアルゴリズムは、その節に記述された構文解析アルゴリズムと同じものを実装することを意図している。

レポート記述子には三つの種類の項目が含まれる。主項目は、データフィールドの定義とグループ化に使用される。大域項目と局所項目はデータフィールドを記述する。局所項目は次の主項目にのみ適用される特性を定義し、大域項目は、その後に定義されるすべての主項目に影響する特性を定義する。

各項目には、その項目に関連する 0、1、2、または 4 バイトのデータを含む項目データフィールドと、bSize フィールドがある。後者は、項目データフィールドの格納に使用するバイト数を記述する。また、各項目には種類を識別するタグがある。

  1. items を、レポート記述子のバイト列をリストに変換した結果とする。その要素は主項目、大域項目、局所項目である。

  2. collections を空の列（要素型: HIDCollectionInfo）として初期化する。

  3. ancestors を空のリストとして初期化する。

  4. localState を空の順序付きマップとして初期化する。

  5. usages を空の列（要素型: unsigned long）として初期化する。

  6. stringIndices を空のリストとして初期化する。

  7. globalStack を空のスタックとして初期化する。

  8. initialGlobalState を空の順序付きマップとして初期化する。

  9. reportId を 0 に初期化する。

  10. initialGlobalState["unitSystem"] を "none" に設定する。

  11. initialGlobalState["unitExponent"] を 0 に設定する。

  12. initialGlobalState["unitFactorLengthExponent"] を 0 に設定する。

  13. initialGlobalState["unitFactorMassExponent"] を 0 に設定する。

  14. initialGlobalState["unitFactorTimeExponent"] を 0 に設定する。

  15. initialGlobalState["unitFactorTemperatureExponent"] を 0 に設定する。

  16. initialGlobalState["unitFactorCurrentExponent"] を 0 に設定する。

  17. initialGlobalState["unitFactorLuminousIntensityExponent"] を 0 に設定する。

  18. initialGlobalState["logicalMinimum"] を 0 に設定する。

  19. initialGlobalState["logicalMaximum"] を 0 に設定する。

  20. initialGlobalState["physicalMinimum"] を 0 に設定する。

  21. initialGlobalState["physicalMaximum"] を 0 に設定する。

  22. プッシュする: initialGlobalState を globalStack に。

  23. 各要素について、item を items から取り出して:

    注: 主項目は [USBIF-HID-CLASS] の 6.2.2.4 節から 6.2.2.6 節に記述されている。Input タグ、Output タグ、Feature タグを持つ項目は、入力、出力、または機能レポート内のフィールドを定義する。項目データフィールドは、主項目が Input タグ、Output タグ、Feature タグのいずれかを持つ場合、データフィールドを記述する複数の真偽値パラメーターを含むビットフィールドである。Collection タグを持つ項目は、現在のコレクション内に入れ子になる新しいコレクションを定義し、現在のコレクションがなければ新しい最上位コレクションを定義する。項目データフィールドは、主項目が Collection タグを持つ場合、コレクションの種類を含む。End Collection タグを持つ項目は、現在のコレクションを閉じる。

    • item が主項目である場合:

      1. item が Input タグ、Output タグ、Feature タグのいずれかを持つ場合:

        1. globalState を、最後の項目（globalStack 内）とする。

        2. reportId を globalState["reportId"] とする。

        3. reportItem を、HID レポート項目を作成する操作を item、localState、globalState、usages、strings を用いて実行した結果とする。

        4. 各要素について、collection を ancestors から取り出して:

          1. reports を次の値とする:

            • collection["inputReports"]（item が Input タグを持つ場合）、

            • collection["outputReports"]（item が Output タグを持つ場合）、または

            • collection["featureReports"]（item が Feature タグを持つ場合）。

          2. reports に、reportId 属性が reportId に等しい項目が含まれる場合、report をその項目とする。

            それ以外の場合:

            1. report を新しい HIDReportInfo 辞書とする。

            2. report["reportId"] を reportId に設定する。

            3. report["items"] を空の列（要素型: HIDReportItem）に設定する。

            4. 追加する: report を reports に。

          3. 追加する: item を report["items"] に。

      2. item が Collection タグを持つ場合:

        1. collection を新しい HIDCollectionInfo 辞書とする。

        2. usage を、最初の項目（usages 内）とする。

        3. サイズ（usages のもの）が 1 より大きい場合、最初の項目を usages から削除する。

        4. collection["usagePage"] を globalState["usagePage"] に設定する。

        5. collection["usage"] を usage に設定する。

        6. collection["type"] を、コレクションの種類を表す値に設定する。

        7. collection["children"] を空の列（要素型: HIDCollectionInfo）に設定する。

        8. collection["inputReports"] を空の列（要素型: HIDReportInfo）に設定する。

        9. collection["outputReports"] を空の列（要素型: HIDReportInfo）に設定する。

        10. collection["featureReports"] を空の列（要素型: HIDReportInfo）に設定する。

        11. ancestors が空である場合、追加する: collection を collections に。

          それ以外の場合:

          1. parent を、最後の項目（ancestors 内）とする。

          2. 追加する: collection を parent["children"] に。

        12. 追加する: collection を ancestors に。

      3. item が End Collection タグを持つ場合、削除する: 最後の項目を ancestors から。

6.2. requestDevice() メソッド

次のrequestDevice() の権限ダイアログは、接続されたデバイスの一覧を提示し、そのうち一つを選ぶようユーザーに求める。

次のrequestDevice() メソッドの手順は次のとおりである:

  1. promise を新しいプロミスとする。

  2. this の関連するグローバルオブジェクトの関連付けられた Document に使用が許可されていないポリシー制御機能の名前が "hid" である場合、拒否する: promise を "SecurityError" DOMException で。その後 promise を返す。

  3. 関連するグローバルオブジェクト（this のもの）が window でない場合、拒否する: promise を "NotSupportedError" DOMException で。その後 promise を返す。

  4. 関連するグローバルオブジェクト（this のもの）が一時的な活性化を持たない場合、拒否する: promise を "SecurityError" DOMException で。その後 promise を返す。

    2. 各要素について、exclusionFilter を options["exclusionFilters"] から取り出して:

      1. exclusionFilter が有効なフィルターでない場合、拒否する: promise を TypeError で。その後 promise を返す。

    1. availableDevices を空のリストとして初期化する。

    2. 各要素について、device を this.[[devices]] から取り出して:

      1. device がいずれかのフィルターに一致する対象が options["filters"] であり、かつ device がいずれかのフィルターに一致することが options["exclusionFilters"] についてはない場合、追加する: device を availableDevices に。

    3. availableDevices 内のデバイス一覧を提示し、サイトによる HID デバイスへのアクセスを許可するようユーザーに求める。

    4. devices を空の列（要素型: HIDDevice）とする。

    5. ユーザーがデバイスを選択しなかった場合、グローバルタスクをキューに入れる。対象の関連するグローバルオブジェクトは this のもので、HID デバイスタスクソースを使用する。タスクでは解決する: promise を devices で。タスクをキューに入れたら、この手順を中止する。

      1. device がHID インターフェイスのうち選択されたデバイスが公開するものを表す場合、device.[[state]] を "closed" に設定し、追加する: device を devices に。

    7. グローバルタスクをキューに入れる。対象の関連するグローバルオブジェクトは device のもので、HID デバイスタスクソースを使用する。タスクでは解決する: promise を devices で。

  8. promise を返す。

6.2.2. HIDDeviceFilter 辞書

dictionary HIDDeviceFilter {
    unsigned long vendorId;
    unsigned short productId;
    unsigned short usagePage;
    unsigned short usage;
};
vendorId メンバー、 型:unsigned long
照合対象のベンダー ID。
productId メンバー、 型:unsigned short
照合対象の製品 ID。vendorId メンバーが存在しない場合、productId は無視される。
usagePage メンバー、 型:unsigned short
照合対象の最上位コレクションの 用途ページ。
usage メンバー、 型:unsigned short
照合対象の最上位コレクションの 用途 ID。usagePage メンバーが存在しない場合、usage は無視される。
デバイスフィルターは、選択ダイアログでユーザーに提示するデバイス一覧を絞り込むために使用される。そのダイアログを作成するのはrequestDevice()である。フィルターが指定されていない場合、除外フィルターのどれにも一致しない接続済みデバイスがすべて含まれる。一つ以上のフィルターが指定されている場合、いずれかのフィルターに一致し、除外フィルターには一つも一致しないデバイスが含まれる。

すべての HIDDeviceFilter メンバーは任意である。各メンバーは一つの規則を指定する。HIDDeviceFilter に一致するには、すべての規則を満たさなければならない。空の HIDDeviceFilter は、どのデバイスにも一致する。

デバイス ID 規則は、ベンダー ID と製品 ID によってデバイスを選択するために使用する。アプリケーションが特定のデバイス専用に設計されている場合や、ベンダー固有の機能に依存する場合に有用である。vendorId 規則を含めると、フィルターは指定したベンダー ID を持つデバイスにのみ一致する。productId 規則も含めると、フィルターは指定したベンダー ID と製品 ID を持つデバイスにのみ一致する。productId は、vendorId 規則なしで指定された場合は無視される。

用途規則は、HID 用途のうちデバイスの最上位コレクションに割り当てられたものによって、デバイスを選択するために使用する。標準的な種類のデバイスを対象に設計されたアプリケーションに有用である。デバイスに一致するには、デバイスのコレクションの少なくとも一つが、すべての用途規則に一致しなければならない。usagePage 規則を含めると、フィルターは指定した用途ページを持つコレクションがデバイスに含まれる場合にのみ一致する。usage 規則も含めると、フィルターは指定した用途ページと用途 ID を持つデバイスにのみ一致する。usage は、usagePage 規則なしで指定された場合は無視される。

デバイス ID 規則と用途規則は組み合わせて使用してもよい。たとえば、アプリケーションは、特定のベンダーのデバイスのうち特定のデバイスクラスを実装するものだけに一致させることを求めてもよい。

exclusionFilters オプションを使用すると、アプリケーションは、requestDevice() が作成する選択ダイアログでユーザーに提示されるデバイスのうち、たとえば特定のデバイスクラスを実装していても期待どおり動作しないことが分かっているものを除外できる。

このHIDDeviceFilter filterについて、有効なフィルターであるのは、以下の手順が次の値を返す場合である:true:

  1. filter が空である場合、false を返す。

  2. filter["productId"] が存在し、filter["vendorId"] が存在しない場合、false を返す。

  3. filter["usage"] が存在し、filter["usagePage"] が存在しない場合、false を返す。

  4. true を返す。

このHIDDevice device がいずれかのフィルターに一致する対象は、次の列 filters（要素型:HIDDeviceFilter）である。ただし、以下の手順が次の値を返す場合に一致する:true:

  1. filters が空である場合、true を返す。

  2. 各要素について、filter を filters から取り出して:

    1. filter がデバイス ID に一致する対象が device であり、かつ filter がいずれかのコレクションに一致する対象が device である場合、true を返す。

  3. false を返す。

このHIDDeviceFilter filter がデバイス ID に一致する（対象: device）。以下の手順が次の値を返す場合に一致する:true:

    2. "productId" が filter に含まれ、filter["productId"] が device.productId に等しくない場合、false を返す。

  2. true を返す。

このHIDDeviceFilter filter がいずれかのコレクションに一致する（対象: device）。以下の手順が次の値を返す場合に一致する:true:

    1. filter がコレクションに一致する対象が collection である場合、true を返す。

  2. false を返す。

    2. "usage" が filter に含まれ、filter["usage"] が collection.usage に等しくない場合、false を返す。

  2. true を返す。

7.1. open() メソッド

次のopen() メソッドの手順は次のとおりである:

  1. promise を新しいプロミスとする。

  2. this.[[state]] が "closed" でない場合、拒否する: promise を "InvalidStateError" DOMException で。その後 promise を返す。

  3. this.[[state]] を "opening" に設定する。

  4. 以下の手順を並列に実行する:

    1. オペレーティングシステムを呼び出して HID デバイスを開く。

    2. 何らかの理由でこれに失敗した場合、グローバルタスクをキューに入れる。対象の関連するグローバルオブジェクトは this のもので、HID デバイスタスクソースを使用する。タスクでは拒否する: promise を "NetworkError" DOMException で。タスクをキューに入れたら、この手順を中止する。

  5. promise を返す。

7.2. close() メソッド

次のclose() メソッドの手順は次のとおりである:

  1. promise を新しいプロミスとする。

  2. this.[[state]] が "forgotten"、"forgetting"、"opening"、または "closing" のいずれかである場合、拒否する: promise を "InvalidStateError" DOMException で。その後 promise を返す。

  3. this.[[state]] を "closing" に設定する。

  4. 各要素について、pendingPromise を this.[[pendingSendReportPromises]] から取り出して:

    1. 拒否する: pendingPromise を "AbortError" DOMException で。

  5. 空にする: this.[[pendingSendReportPromises]] を。

  6. 各要素について、pendingPromise を this.[[pendingSendFeatureReportPromises]] から取り出して:

    1. 拒否する: pendingPromise を "AbortError" DOMException で。

  7. 空にする: this.[[pendingSendFeatureReportPromises]] を。

  8. 各要素について、pendingPromise を this.[[pendingReceiveFeatureReportPromises]] から取り出して:

    1. 拒否する: pendingPromise を "AbortError" DOMException で。

  9. 空にする: this.[[pendingReceiveFeatureReportPromises]] を。

  10. 以下の手順を並列に実行する:

    1. オペレーティングシステムを呼び出して HID デバイスを閉じ、関連するすべてのリソースを解放する。

    2. this.[[state]] を "closed" に設定する。

    3. グローバルタスクをキューに入れる。対象の関連するグローバルオブジェクトは this のもので、HID デバイスタスクソースを使用する。タスクでは解決する: promise を undefined で。

  11. promise を返す。

7.3. forget() メソッド

注: ユーザーエージェントは、API 間で権限を統合してもよい。たとえば、WebHID と WebUSB のデバイスアクセスを、統一された低水準デバイスアクセス権限で追跡することが考えられる。このため、このメソッドは将来、追加の（まだ規定されていない）権限も取り消すことがあり得る。

  2. 以下の手順を並列に実行する:

    1. 各要素について、device を this.[[devices]] から取り出して:

      1. device が HIDDevice とデバイスアクセス権限を共有していない場合、次のデバイスに進む。

      2. device.[[state]] を "forgetting" に設定する。

      3. 各要素について、pendingPromise を device.[[pendingSendReportPromises]] から取り出して:

        1. 拒否する: pendingPromise を "AbortError" DOMException で。

      4. 空にする: device.[[pendingSendReportPromises]] を。

      5. 各要素について、pendingPromise を device.[[pendingSendFeatureReportPromises]] から取り出して:

      9. ユーザーエージェントを呼び出して、すべてのHID インターフェイスのうち device が公開するものへのアクセスを取り消す。

      10. device.[[state]] を "forgotten" に設定する。

10. HIDCollectionInfo 辞書

dictionary HIDCollectionInfo {
    unsigned short usagePage;
    unsigned short usage;
    octet type;
    sequence<HIDCollectionInfo> children;
    sequence<HIDReportInfo> inputReports;
    sequence<HIDReportInfo> outputReports;
    sequence<HIDReportInfo> featureReports;
};

デバイスがシステムに初めて接続されたとき、システムはレポート記述子を、デバイスが公開する各HID インターフェイスについて取得しなければならない。レポート記述子はバイト列であり、デバイスがサポートする各レポートの配置を記述する階層的なデータ構造に展開できる。このデータ構造の要素を項目という。互いに関係を持つ項目の集まりをコレクションという。

HIDCollectionInfo オブジェクトは、レポート記述子内の一つのコレクションを表す。コレクションが入れ子のコレクションを含む場合、入れ子のコレクションは children の要素として含まれる。

inputReports、outputReports、featureReports の各属性は列を含み、その要素である HIDReportInfo は、このコレクション内に記述された各レポートに関する情報を提供する。最上位コレクションの場合、HIDReportInfo はレポートを構成するすべての項目を平坦化した表現である。この表現では、入れ子のコレクション内の項目を最上位コレクション内の項目と混在させる。入れ子のコレクションの場合、HIDReportInfo には、そのコレクションとその入れ子のコレクションに含まれる項目のみを含める。

usagePage メンバー、 型:unsigned short
次の用途ページの成分。これはHID 用途のうち、このコレクションに関連付けられたものに属する。

HID 用途は、アプリケーションが解釈して項目またはコレクションの目的と意味を識別できる定数である。HID 用途は unsigned long 値であり、unsigned short 型の用途ページを上位ビットに、unsigned short 型の用途 ID を下位ビットにして構成する。標準的なHID 用途の値は、[USBIF-HID-CLASS] およびUSB Implementers Forum が発行するその他の文書に記述されている。

HID 用途のうち、デバイスが公開する最上位コレクションのものは、デバイスの大まかな種類を識別するために使用される。

usage メンバー、 型:unsigned short
次の用途 IDの成分。これはHID 用途のうち、このコレクションに関連付けられたものに属する。

用途 ID は、個々のHID 用途を用途ページ上で選択するために使用される。慣例により、用途 ID の 0x01 から 0x1F は最上位コレクション用に予約されている。

type メンバー、 型:octet
次のものを表す値:コレクションの種類.
コレクションの種類 値
物理 0x00
アプリケーション 0x01
論理 0x02
レポート 0x03
名前付き配列 0x04
用途切り替え 0x05
用途変更 0x06
将来の使用のために予約 0x07 から 0x7F
ベンダー定義 0x80 から 0xFF

各コレクションの種類は、まとめられた項目間の異なる関係を記述する。[USBIF-HID-CLASS] の 6.2.2.6 節に、コレクションの種類の詳細がある。

children メンバー、 型: sequence<HIDCollectionInfo>
次の列（要素型: HIDCollectionInfo）。このコレクション内に入れ子になったコレクションを表す。
inputReports メンバー、 型: sequence<HIDReportInfo>
次の列（要素型: HIDReportInfo）。このコレクション内に記述された入力レポートを表す。
outputReports メンバー、 型: sequence<HIDReportInfo>
次の列（要素型: HIDReportInfo）。このコレクション内に記述された出力レポートを表す。
featureReports メンバー、 型: sequence<HIDReportInfo>
次の列（要素型: HIDReportInfo）。このコレクション内に記述された機能レポートを表す。

11. HIDReportInfo 辞書

dictionary HIDReportInfo {
    octet reportId;
    sequence<HIDReportItem> items;
};

HIDReportInfo は、レポート記述子内の一つの入力、出力、または機能レポートを表す。

reportId メンバー、 型:octet
このHID インターフェイス がレポート ID を使用するとは、レポートの転送ごとに 1 バイトの識別接頭辞を先頭に付けることをいう。reportId メンバーは、このレポートの接頭辞である（インターフェイスがレポート ID を使用する場合）。それ以外の場合は 0 である。
items メンバー、 型: sequence<HIDReportItem>
次の列（要素型: HIDReportItem）。このレポートのフィールドを表す。

isAbsolute メンバー、 型:boolean
true（データが絶対値、つまり固定した原点に基づく場合）。またはfalse（データが相対値、つまり前回のレポートからの値の変化を示す場合）。
isArray メンバー、 型:boolean
true（項目がレポート内に配列データフィールドを作成し、各データフィールドが押されたボタンまたはキーに対応するインデックスを含む場合）。またはfalse（項目がレポート内に可変データフィールドを作成し、各データフィールドが値を含む場合）。
isBufferedBytes メンバー、 型:boolean
true（項目が固定長のバイトストリームを出力する場合）。またはfalse（項目が数値量である場合）。
isConstant メンバー、 型:boolean
true（項目が静的な読み取り専用フィールドであり、変更できない場合）。またはfalse（項目が、変更可能なデバイスデータを含むレポートフィールドを定義する場合）。
isLinear メンバー、 型:boolean
true（項目が、測定対象と報告値の間の線形関係を表す場合）。またはfalse（データが何らかの方法で処理されている場合）。
isRange メンバー、 型:boolean
true（項目が用途を次のHID 用途の範囲から割り当てる場合。その範囲の定義はusageMinimumとusageMaximumである）。またはfalse（項目が持つのは次の列であり、その要素はHID 用途の値である）。格納先は usages.
isVolatile メンバー、 型:boolean
true（項目の値がホストとのやり取りなしに変わり得る場合）。またはfalse（項目の値を変更するのはホストのみにするべき場合）。

hasNull メンバー、 型:boolean
true（項目が、有意なデータを送信しないヌル状態を持つ場合）。またはfalse（ヌル状態を持たない場合）。ヌル状態では、項目は指定された次の範囲外の値を報告する:logicalMinimumとlogicalMaximum.
hasPreferredState メンバー、 型:boolean
true（ユーザーが操作部を物理的に操作していないときに戻る優先状態を、項目が持つ場合）。またはfalse（項目が優先状態を持たない場合）。
wrap メンバー、 型:boolean
true（項目の値が上限または下限に達すると折り返す場合）。またはfalse（項目の値が折り返さない場合）。

もしisRange がtrueであるか、この項目に関連付けられたHID 用途の値が存在しない場合、usagesは undefined でなければならない。

isRange が false である場合、usages は列であり、その値はこの項目に関連付けられたHID 用途である。

usageMinimum メンバー、 型:unsigned long
もしisRange がtrueである場合、usageMinimumには、最小のHID 用途値（この項目に関連付けられた用途範囲内）が含まれる。

usageMaximum メンバー、 型:unsigned long
もしisRange がtrueである場合、usageMaximumには、最大のHID 用途値（この項目に関連付けられた用途範囲内）が含まれる。

13. HIDUnitSystem 列挙型

[USBIF-HID-CLASS] の 6.2.2.7 節は、SI 線形、SI 回転、英国式線形、英国式回転という四つの標準単位系を定義する。各項目は、これら四つの単位系のいずれか、ベンダー定義の単位系、または単位系なしを使用する。

enum HIDUnitSystem {
    "none", "si-linear", "si-rotation", "english-linear",
    "english-rotation", "vendor-defined", "reserved"
};
"none"
単位系なし。項目が単位定義を持たないことを示す。
"si-linear"
SI 線形単位系は、センチメートル、グラム、秒、ケルビン、アンペア、カンデラを使用する。
"si-rotation"
SI 回転単位系は、ラジアン、グラム、秒、ケルビン、アンペア、カンデラを使用する。
"english-linear"
英国式線形単位系は、インチ、スラグ、秒、華氏度、アンペア、カンデラを使用する。
"english-rotation"
英国式回転単位系は、度、スラグ、秒、華氏度、アンペア、カンデラを使用する。
"vendor-defined"
ベンダー定義の単位系。
"reserved"
デバイスが単位系として予約値を使用したことを示す。

14. 使用例

ページからアクセス可能なデバイスの一覧を取得する。既定では、ページはどのデバイスへのアクセス権限も付与されていないため、何にもアクセスできない。 
document.addEventListener('DOMContentLoaded', async () => {
  let devices = await navigator.hid.getDevices();
  devices.forEach(device => {
    console.log(`HID: ${device.productName}`);
  });
});
HID デバイスの接続と切断のイベントリスナーを登録する。 
navigator.hid.addEventListener('connect', ({device}) => {
  console.log(`HID connected: ${device.productName}`);
});

navigator.hid.addEventListener('disconnect', ({device}) => {
  console.log(`HID disconnected: ${device.productName}`);
});
デバイスは次のメソッドからはアクセスできず、getDevices()接続イベントも生成しない。ただし、デバイスへのアクセス権限が付与された後は可能になる。ページは権限を要求してもよい。そのために使用するのはrequestDevice()である。この例では、ページは次のベンダー ID 0xABCDを持つデバイスへのアクセスを要求する。また、デバイスは条件を満たさなければならない。その条件は、コレクションを持ち、その用途ページが Consumer（0x000C）、その用途 IDが Consumer Control（0x0001）であること。次の製品 ID 0x1234を持つデバイスは、正常に動作しないことが報告されている。 
let requestButton = document.getElementById("request-hid-device");
requestButton.addEventListener("click", async () => {
  let device;
  try {
    const devices = await navigator.hid.requestDevice({
      filters: [
        {
          vendorId: 0xabcd,
          usagePage: 0x000c,
          usage: 0x0001,
        },
      ],
      exclusionFilters: [
        {
          vendorId: 0xabcd,
          productId: 0x1234,
        }
      ],
    });
    device = devices[0];
  } catch (error) {
    console.log("An error occurred.");
  }

  if (!device) {
    console.log("No device was selected.");
  } else {
    console.log(`HID: ${device.productName}`);
  }
});
入力レポートイベントのイベントリスナーを登録する。 
device.oninputreport = ({device, reportId, data}) => {
  console.log(`Input report ${reportId} from ${device.productName}:`,
              new Uint8Array(data.buffer));
};

if (!device.opened)
  await device.open();
出力レポートを送信する。 
try {
  if (!device.opened)
    await device.open();

  const outputReportData = new Uint8Array([0x12, 0x34, 0x56, 0x78]);
  await device.sendReport(0x05, outputReportData);
  console.log("Output report sent");
} catch (error) {
  console.log("An error occurred.")
}
機能レポートの読み取りと書き込みを行う。 
try {
  if (!device.opened)
    await device.open();

  const oldFeatureData = await device.receiveFeatureReport(0x80);
  console.log("Feature report received:", new Uint8Array(oldFeatureData.buffer));

  const newFeatureData = new Uint8Array([0x12, 0x34, 0x56, 0x78]);
  await device.sendFeatureReport(0x80, newFeatureData);
  console.log("Feature report sent");
} catch (error) {
  console.log("An error occurred.")
}

15. HID ブロックリスト

この仕様は、https://github.com/whatwg/hid リポジトリー内のブロックリストファイルに依存して、ウェブサイトがアクセスできる HID デバイスの集合を制限する。

次の操作、すなわちブロックリストの構文解析を URLurlに対して行った結果は、次の列であり、その要素は辞書オブジェクトである。これは次の URL を取得し、urlその内容を JSON として構文解析することで生成する。

HID ブロックリストは、ブロックリストの構文解析を https://github.com/whatwg/hid/blob/main/blocklist.txt に対して行った結果である。

レポートがブロックされたレポートであるのは、以下の手順が次の値を返す場合である:true:

  1. 各要素について、rule をHID ブロックリストから取り出して:

    1. レポートがブロックリスト規則によってブロックされる対象の規則が rule である場合、true を返す。

  2. false を返す。

レポートがブロックリスト規則によってブロックされる（対象の規則: rule）のは、以下の手順が次の値を返す場合である:true:

  1. reportId を、このレポートのレポート ID とする。ただし、HID インターフェイスがレポート ID を使用するのでない場合は、0 とする。

  2. reportType を、入力レポートの場合は "input"、出力レポートの場合は "output"、機能レポートの場合は "feature" とする。

  3. collection を、このレポートを含む最上位コレクションとする。

  4. rule が "vendor" を含み、rule["vendor"] が device.vendorId でない場合、false を返す。

  5. rule が "product" を含み、rule["product"] が device.productId でない場合、false を返す。

  6. rule が "reportId" を含み、rule["reportId"] が reportId でない場合、false を返す。

  7. rule が "reportType" を含み、rule["reportType"] が reportType でない場合、false を返す。

  8. rule が "usagePage" を含み、rule["usagePage"] が collection["usagePage"] でない場合、false を返す。

  9. rule が "usage" を含み、rule.["usage"] が collection["usage"] でない場合、false を返す。

  10. true を返す。
