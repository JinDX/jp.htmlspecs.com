1. はじめに

WebRTC Diagnostic Logging API は、Web アプリケーションが、ユーザーエージェントによって実行される WebRTC 関連操作の内部診断 ログの収集を開始、終了、および破棄するためのプログラムインターフェイスを提供する。 これらの診断ログがアプリケーションに公開されることはない。代わりに、それらは ユーザーが管理する場所に保存され、ユーザー エージェントのベンダーと共有される場合がある。 診断ログの収集および保存にはユーザーによる明示的な 承認が必要であり、アプリケーションは診断ログ操作が 成功したか失敗したかを知ることはない。診断ログの内容も 実装の詳細である。 この API がサポートすることを意図しているユースケースは次のとおりである。

  • アプリケーションがログの収集を要求する。これらのログは、 開発者がアプリケーション内のバグを診断するために使用できる。 アプリケーションのユーザーは、バグの修正やその他の方法でアプリケーションを改善する 助けとなるよう、これらのログをアプリケーション開発者に提供できる。組織は、 バグを診断したり、内部 WebRTC 配備を 改善したりするために、ユーザーからこれらのログを収集できる。

  • ユーザーは、ログがユーザーエージェントのベンダーと共有されるよう設定できる。これは、 アプリケーション開発者がユーザーエージェントにバグがあると疑い、 ユーザーエージェントの開発者によるバグ修正を支援するためにログを提供したい場合に 有用である。このユースケースをサポートするため、API は 診断ログセッションを識別するために使用できる UUID（例えば、バグ報告内で）を返す。この 仕組みによって診断ログがアプリケーションに公開されることはない。

2. セキュリティとプライバシー

これらの診断ログは、WebRTC 関連機能を実装するために ユーザーエージェントによって実行される内部操作に関する情報を収集する。これらの診断ログには、 Web アプリケーションに公開されない情報が含まれる可能性があり、そのため API はいかなる方法でもこれらのログを Web アプリケーションに公開してはならない。ログは、 ユーザーの承認を条件として、（例えば帯域外アップロードを介して） ユーザーエージェントのベンダーと共有され、ユーザーエージェントのバグ修正や ユーザーエージェントに対するその他の改善の支援に使用される場合がある。

診断ログの収集、保存、およびアップロードにはユーザーによる明示的な 承認が必要である。この承認の具体的な仕組みは 実装定義である。承認を実装する選択肢には、 専用 UI、設定ファイル、エンタープライズポリシー、 プロンプト、またはそれらの組み合わせなどが含まれるが、これらに限定されない。承認は特定の オリジンに限定される場合がある。これらの承認の状態がアプリケーションに公開されることはない。 したがって、API は成功を保証しない。

3. RTCPeerConnection インターフェイスの拡張

API は、RTCPeerConnection インターフェイス上の一連の静的メソッドとして公開される。

[
  Exposed=Window
] partial interface RTCPeerConnection {
  static Promise<DOMString> startDiagnosticLogging(optional RTCDiagnosticLoggingOptions options = {});
  static Promise<undefined> finishDiagnosticLogging(optional RTCDiagnosticLoggingOptions options = {});
  static Promise<undefined> discardDiagnosticLogging();
};

3.1. 辞書

RTCDiagnosticLoggingOptions はログ セッションの設定を提供する。

dictionary RTCDiagnosticLoggingOptions {
  record<DOMString, DOMString> metadata;
};

3.2. 内部スロット

関連するグローバルオブジェクトが、 [[RTCDiagnosticLoggingSessionId]] 内部スロットを持つものとし、これは nullに初期化される。

3.3. メソッド

3.3.1. startDiagnosticLogging(options)

startDiagnosticLogging(options) メソッドは、 診断ログセッションの開始を試みる。

このメソッドが呼び出されたとき、ユーザーエージェントは次の手順を実行しなければならない。

  1. optionsをこのメソッドの第1引数とする。

  2. metadataをoptionsのmetadata メンバーとする。

  3. metadataのサイズが 5 より大きい場合、またはmetadataの任意のエントリー key → valueが、長さ 100 より大きい場合、 TypeErrorで拒否されたプロミスを返す。

  4. pを新しいプロミスとする。

  5. 並行して、次の手順を実行する。

    1. uuidをランダムに生成された UUID [rfc4122]とする。 フィンガープリンティングを 避けるため、実装は UUID を生成するときに RFC 4122 の 4.4 節の形式を使用するべきである。

    2. docを関連するグローバルオブジェクトに関連付けられた文書とする。

    3. [[RTCDiagnosticLoggingSessionId]] 内部 スロットがnullでない場合、DOMException オブジェクトでpを拒否する。そのname 属性の値を "InvalidStateError" とし、これらの手順を中止する。

    4. uuidを[[RTCDiagnosticLoggingSessionId]] 内部スロットに保存する。

    5. pをuuidで解決する。

    6. uuidによって識別される内部 WebRTC アクティビティのログセッションを開始する。

  6. pを返す。

ログセッションが開始すると、pが解決した後にdocによって生成される WebRTC 関連アクティビティは ユーザーエージェントによってログに記録されてもよい。 ログにはmetadataまたはそれから派生した情報が含まれてもよい。 ログセッションはuuidによって識別され、これは ログを参照するために使用できる（例えば、バグ報告内で）。

3.3.2. finishDiagnosticLogging(options)

finishDiagnosticLogging(options) メソッドは、進行中の 診断ログセッションを終了する。

このメソッドが呼び出されたとき、ユーザーエージェントは次の手順を実行しなければならない。

  1. optionsをこのメソッドの第1引数とする。

  2. metadataをoptionsのmetadata メンバーとする。

  3. metadataのサイズが 5 より大きい場合、またはmetadataの任意のエントリー key → valueが、長さ 100 より大きい場合、TypeErrorで拒否されたプロミスを返す。

  4. pを新しいプロミスとする。

  5. 並行して、次の手順を実行する。

    1. [[RTCDiagnosticLoggingSessionId]] 内部 スロットがnullである場合、DOMException オブジェクトで pを拒否する。そのname 属性の値を "InvalidStateError" とし、これらの手順を中止する。

    2. [[RTCDiagnosticLoggingSessionId]] によって識別されるログセッションを停止する。

    3. [[RTCDiagnosticLoggingSessionId]] を nullに設定する。

    4. pをundefinedで解決する。

  6. pを返す。

pが解決した後、ユーザーエージェントはdocによって生成される WebRTC 関連アクティビティを ログに記録してはならない。

3.3.3. discardDiagnosticLogging()

discardDiagnosticLogging() メソッドは、 進行中の診断ログセッションを破棄し、そのセッションに関連付けられたすべてのログデータを 削除する。

このメソッドが呼び出されたとき、ユーザーエージェントは次の手順を実行しなければならない。

  1. pを新しいプロミスとする。

  2. 並行して、次の手順を実行する。

    1. [[RTCDiagnosticLoggingSessionId]] 内部 スロットがnullである場合、DOMException オブジェクトで pを拒否する。そのname 属性の値を "InvalidStateError" とし、これらの手順を破棄する。

    2. uuidを[[RTCDiagnosticLoggingSessionId]]の値とする。

    3. [[RTCDiagnosticLoggingSessionId]] によって識別されるログセッションを破棄する。

    4. [[RTCDiagnosticLoggingSessionId]] を nullに設定する。

    5. pをundefinedで解決する。

  3. pを返す。

pが解決した後は、次のとおりとする。

  • ユーザーエージェントはdocによって生成される WebRTC 関連アクティビティをログに記録してはならない。

  • ユーザーエージェントは、uuidによって識別されるセッションに関連付けられた すべてのログデータを削除しなければならない。
