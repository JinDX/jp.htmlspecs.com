概要

RDF [RDF11-CONCEPTS] は、世界について記述するグラフベースのデ ータモデルを示し、その情報グラフに基づく推論の 基盤を提供します。グラフの集合を比較したり、 デジタル署名を付けたり、ハッシュアルゴリズムで 短い識別子を生成したりする必要が生じることが あります。この文書は、これらの操作を可能にする RDF データセット の正規化アルゴリ ズムを示します。

1. はじめに

この節は非規範的です。

データ科学者は、特定の目標を達 成するという文脈で正規化を論じ ます。同じ情報を異なる方法で表 せる場合があるため、それらを 一つの標準表現に変換する必要が しばしば生じます。標準表現が あれば、二つのデータ集合の差を 容易に判定し、特定のデータ集 合に暗号学的に強いハッシュ識別 子を生成し、また後で検証でき るデジタル署名を付けられます。

特に、この仕様はグラフの集合である RDF データセットの正規化を扱います。有向グラフは同じ 情報を複数の方法で表せるため、上述の 目標や、偶然見つかるかもしれない他の 目的を達成するには正規化が必要です。

アルゴリズムの時間計算量の点では、大半の RDF データセット は比較的速く正規化できます。た だし、グローバルに一意な識別子 を持たないノードを含むものは 難しくなります。その正規化には グラフ同型 問題が生じ、最悪の場合には高速な 解法が難しいと考えられています。 幸い、現実の既存データが最悪の場 合になることはほぼなく、新しい データもそれを避けてモデル化でき ます。問題のあるデータセット（ 7.1 データセット・ポイズニング参照）を検出したソフトウェアは、正当 な入力ではなくサービス拒否攻撃の試み と見なして中止することもできます。

この 文書は RDF データセット の正規直列化形式を、入力の RDF データセット から生成するアルゴリ ズムを示します。これを RDF 正規化アルゴリズム バージョン 1.0 、略して RDFC-1.0と呼びます。

注

RDF 1.1 概念および抽象構文 [RDF11-CONCEPTS] では 言語タグ付き文字列の表現が明確で はありません。 言語タグ の xx-YY 形式は大文字と小文字を区別し ません。実装はすべて小文字の xx-yy、元 の xx-YY、または [BCP47] の 表記規約を使う可能性があり、正規形式とハ ッシュ値が異なる結果になります。

  • 正規化アルゴ リズムは、 言語タグ xx-YY が大文字と小文字を区別しないという RDF 1.1 の定義に基づきます。この問題に気づかないと、正規化結果が異なる可能性があります。
  • 利用者のコミュニティは小文字の 言語タグを使うことに合意するのがよく、一部の 実装が言語タグを正規化してハッシュ値 に影響することにも注意が必要です。
  • RDF の将来の発展でこの問題が規定され、RDF 環境が対応を求められる可能性があり、 RDFC-1.0の更新につながることも考えられます。
注

B. URDNA2015 に 、 RDF データセット正規化 [CCG-RDC-FINAL] で公開されたアルゴリズムとの比較があります。

1.1 データセット正規化の用途

グラフやデータセットの正規化が重要となるユースケースには、次のものがあります。

  • ある直列化が別の直列化と同型か判定する。
  • 直列化や形式に依存せず、グラフ（データセット）にデジタル署名する。
  • 二つのグラフ（データセット）を比較して差を見つける。
  • RDF ソースを遠隔更新する際に変更集合を伝える。

これらの多くのユースケースに正規化アルゴリズムは必要ですが、それだけで十分とは限りません。RDF グラフやデータセットでの 空白ノード の利用には長い歴史があり、避けられない複雑さを生みます。空白ノードはさまざまな目的に使われます。

  • ノードの周知の識別子が分からない場合や、文書の作成者がそのノードを一意に命名しないことを選ぶ場合、
  • ノードがグラフの部分同士をつなぐために使われ、ノード自体には関心がない場合（例えば RDF コレクション 、[RDF11-MT]）、
  • 意図的に難しいグラフのトポロジーを作ろうとする場合。

さらに RDF の意味論では、RDF 文書を逆直列化すると一意な 空白ノードが作られま す。ただし 、毎回その 空白ノード が同じリソースを識別すると 判定できる場合を除きます。 空白ノード識別子 は具体的な RDF 構文の要素 であり、永続性や移植性を意 図しないためです。抽象 RDF モデルでは空白ノードに識 別子はありません（ただし、 一部の RDF ストアは安定し た識別子を使用し、移植可 能にすることがあります）。 空白ノード （[RDF11-CONCEPTS]）を参照してください。

RDF では Skolem IRIにより、空白ノードを外部から識別可能な形で公開できます。特定の RDF ストアで、具体構文の空白ノードを IRIに置き換え、そのストア内で繰り返し 同じノードを識別できます。ただし、 異なる RDF ストアや他の具体表現で 同じグラフを扱う場合には、一般に役 立ちません。いずれにせよ、一つの ストアや直列化に定義された安定した 空白ノード識別子 は任意のもので、通 常は利用文脈と関 連付けられません。

この仕様は、同じ RDF グラフ（データセット）の異なる直列化に対し、安定した 空白ノード識別子 を繰り返し作るアルゴリズムを 定義します。各直列化が個別の 空白ノード識別子 を使っていても、各 空白ノード を接続先のノードに 基づいて特定します。 その結果、得られた 正規化データセットの正規直列化をハッシュしてグラフの署名を得ら れ、同型判定とデジタル署名に利用できます。こ の仕様はそのグラフ署名自体を定義しません。

グラフ（データセット）の他の部分が変わっ ても空白ノード識別子が安定する場合があり 、その場合は二つのグラフの差を計算できま す。例えば、空白ノードを含まないトリプル だけが変わる場合や、既存ノードとの自己同 型による混同を生じない新しい空白ノードを 追加する場合です。生成される識別子を変え る情報があれば、差分が実際より多くの変更 を示す可能性があります。また、元のデータ セットが N-Quads 文書なら、その元の識別子と 正規化データセットで発行された識別子を関連付けられる場合があります。

注

この仕様で他の ハッシュアルゴリズム を使うことはできま すが、利点と欠点を慎 重に検討すべきです 。特に、関連するアル ゴリズムを示さない 正規 N-Quads 形式 や 発行済み識別子マップ の表現では重 要です。同じ 出力を再現す る必要がある 用途では、 正規 N-Quads 形式の生成に用いた内部ハッシュアルゴリズムを明確に表明または伝達することが期待されます。

3. 用語

3.1 この仕様で定義する用語

正規 N-Quads 形式
クアッドの正規表現は A. N-Quads の正規形式で定義し ます。 正規 N-Quads 形式 のクアッドは、存在する場合の グラフ名を 主語と同じ方法で表し、単一の LF （改行、コードポイント U+000A）で終わります。
正規化関数
正規化関数 は RDF データセット を 同型のデータセット [RDF11-CONCEPTS] に写像します。二つのデータセットが同じ正規結果を生むのは、それらが 同型である場合に 限ります。 RDFC-1.0 は 正規化関数を実装します。合理的な時 間で終了できないように構 成されたデータセット（ 7.1 データセット・ポイズニング参照 ）で は、 部分正規化関数と見なせます。
正規化データセット
正規化データセット は次の組合せです。
  • RDF データセット 、す なわち 入力データセット、
  • 入力空白ノード識別子マップ 。入力デー タセットの 空白ノード を 空白ノード識別子に対応付けるもの、および
  • 発行済み識別子マップ 。 正規発行器 が持ち、入力データセットの識別 子を正規識別子に対応付けるもの
正規化データセット の具体的な直列化は、MUST の要件とし てすべての 空白ノード を正規の 空白ノード識別子でラベル付けしなければなりません。
伝播経路
空白ノードから出る各関連 言及 の特定の列挙です 。推移的に関連する 言及 を再帰的に含み、名前付 きノード、または特定の 識別子発行器 がラベル付け済みの空白ノードに 達すると止まります。伝播経路は RDFC-1.0 で文字列として符号化、操作されます。（構築の詳細は 4.8 N 次クアッドのハッシュ を参 照。）
ハッシュ

ハッシュアルゴリズム
既定のハッシュアルゴリズムは RDFC-1.0で使う SHA-256 [FIPS-180-4].

実装は MUST の要件として ハッシュアルゴリズムを指定するパラメーターをサポートし、 MUST の要件として SHA-256 と SHA-384 [FIPS-180-4] に対応する必要があります。他のハッシュアルゴリズムの指定にも対応することが SHOULD （推奨）です。別のアルゴ リズムでは通常、既定とは 異なる出力になります。

注

正規 N-Quads の結果のハッシュダイジェストを作るアプリケーションにも、同じ既定のハッシュアルゴリズムを使うことは期待していません。

注
実装や環境によっては、解析済みまたは抽象 データセットに識別子を保持するなど、より 直接扱うことがあります。アルゴリズム外で も入力と出力の識別子を対応付けられるよう 、それらを再利用することが期待されます。

アルゴリズムに入力する抽象 RDF データセット 。

4. 正規化

正規化とは 入力データセット を 直列化された正規形式に変換する処理です。 同じ情報を含む二つの 入力データセット は、並び 方にかか わらず同じ 直列化された正規形式に変換されます。有向グラフをノードと辺の 集合として決定的に順序付ける必要がありま す。すべてのノードにグローバルに一意な識 別子があれば容易ですが、そうでなければ難し くなります。一意な識別子のないノードには 決定的な識別子を発行しなければなりません。

注

この仕様の 正規化データセット は空白ノードの安定した識別子を含み、実用 時には常にその正規直列化を生成します。

将来複数の正規化アルゴリズムが存在する可能性があるため、識別用に「RDF 正規化アルゴリズム バージョン 1.0」（RDFC-1.0）と名付けます。

図 1 は RDFC-1.0の概要で、手順 1～7 は 4.4.3 アルゴリズムの各手順に対応します。

4.1 概要

この節は非規範的です。

正規ラベルを決めるため、 RDFC-1.0 は各空白ノード に接続する情報 を調べます。一次 情報が一意なら 識別子発行アルゴリズムですぐに正規識別子を発行できま す。一意でなければ、データセッ ト全体で推移的につながるすべて の情報を求める必要があります。 4.6 一次クアッドのハッシュ で、一次ハッシュにより 一次情報を定義します。

各空白ノードの情報からハ ッシュを計算し、関連する 言及 を符号化 します。 ハッシュ （文字列 sのもの ）は、 s を暗号学的ハッシュ関数に渡した 結果の小文字の十六進表現です。 RDFC-1.0 は既定で SHA-256 [FIPS-180-4] を使います。

注

この仕様の「次数」 は、データセットの任 意の二つのノードの 離心数 や 半径 を日常的な言 葉で述べるも のです。「六次の隔たり」などの隔たりの次数とも関連します。一次情報が一 意なノードは、半径が一のノードと考えられます。

4.2 正規化状態

正規化アルゴリズ ムの実行時は、 正規化状態というデータ構造で状態を追跡すると便利です。 正規化状態 に含む情報を以下に示します。

空白ノードからクアッドへのマップ
マップ で、 空白ノード識別子 を、それ が現れる クアッド （ 入力データセット内）に対応付けます。
ハッシュから空白ノードへのマップ
マップ で、 ハッシュ を リスト （ 空白ノード識別子のもの）に対応付けます。
正規発行器
識別子発行器を接 頭辞 c14n （canonicalization の略）で初期化し、正規 空白ノード識別子を発行します。
注
すべての 空白ノード がこの規則を 使うため、 RDF データセット が異なる 二つの RDF グラフ からなる場合、各グラフ を独立に扱う場合とは異 なる識別子になります。 自己同型や重複する文によって も起こりますが、結果の ハッシュ と、その ハッシュ 固有の発行連番を使 う識別子なら小さな 変更に耐えやすく、 RDF 差分に役立つ可能性が高まります。

4.3 空白ノード識別子発行器の状態

正規化アルゴリズムは 空白ノードに識別子を発 行します。 識別子発行アルゴリズム が 識別子発行器 を使って 行います。 識別子発行器 が追跡する情報を 以下に示します。

識別子接頭辞
識別子接頭辞は 空白ノード識別子の先頭に使う文字列で、正規 化アルゴリズムが指定する文 字列に初期化します。新しい 空白ノード識別子は接 頭辞と 識別子カウンターを連結して作ります。例えば c14n は適切な 識別子接頭辞 の初期値で、 空白ノード識別子 として c14n1などを生成します。
識別子カウンター
識別子接頭辞 に付 加して 空白ノード識別子を作るカウンターで、 0に初期化します。
発行済み識別子マップ
順序付きマップ で、 空白ノード識別子 を発行済み識別子に対応付け、 同じ既存識別子への複数発行を 防ぎます。また、発行後の時点で 空白ノード に識別子を割り 当てられます。

4.4 正規化アルゴリズム

正規化アルゴリズムは 入力データセット を 正規化データセット に変換し、複雑 すぎると判定し た場合はエラーを 発生させます。 空白ノード （ 入力データセット内）すべてに決定的な識別子を割り当てます。

4.4.1 概要

この節は非規範的です。

RDFC-1.0 は RDF データセット の各 空白ノード に正規識別子を割り当てて 正規ラベルを付けます。 RDFC-1.0ではデータセット D を クアッド < s, p, o, g > の集合で表します。グラフ成分 g が空なのは、 トリプル < s, p, o > が 既定グラフにある場合に限ります。二 つのデータセットに対し、 RDFC-1.0 は同型（空白ノード識別子を除いて同じ）の場合に限り同 じ正規ラベル付きクアッド列を返すことが期待されます。

RDFC-1.0 は以下で説明する複 数の副アルゴリズム からなります。まず RDFC-1.0の全体像を示します。

  1. 初期化。 4.2 正規化状態に従い必要な状態 を初期化します。 正規化データセット も、 入力データセット （不 変）と 入力空白ノード識別子マップ （可能なら入力の識別子を保持し、それ以 外は任意に割り当てる）で初期化します。 発行済み識別子マップ は 正規発行器 からアルゴリズム完了時に追加します。
  2. 一次ハッシュの計算。 4.6 一次クアッドのハッシュで各空白ノードの一次ハッシュを計算します。
  3. 一意なノードの正規ラベル付け。 4.5 識別子発行アルゴリズムによ り、 Unicode コードポイント順に一次ハッシュが一意な各空白ノードへ正規識別子を割り当てます。
  4. 一意でないノードの N 次ハッシュ計算。重複する一 次ハッシュを Unicode コードポイント順に処 理し、 4.8 N 次クアッドのハッシュ で対応する未ラベルの各空白ノードの N 次ハッシュを計算します。
  5. 残りのノードの正規ラベル付け。N 次ハッシュの Unicode コードポイント順 に 、 4.5 識別子発行アルゴリズムで対応するノードに正規識別子を発行します。同じ N 次ハッシュを持つ複数ノードへの発行順序は問いません。
  6. 完了。 直列化された正規形式 （ 正規化データセットのもの）を返 します。または 正規化データセット を 、 入力空白ノード識別子マップ と 発行済み識別子マップを含めて返します。

4.5 識別子発行 アルゴリズム

このアルゴリズムは新しい 空白ノード識別子 を、 既存の 空白ノード識別子に対して発行 し、新しい 空白ノード識別子 の発行順を追跡する状態も更新します。デー タセット内の他のノードと同型な空白ノード の正規ラベル付けには発行順が重要です。

4.5.1 概要

発行済み識別子マップ により 既存の 空白ノード識別子 （ 入力データセット 内）を新しい 空白ノード識別子 に対応付けます。 識別子接頭辞 （c14n）に増加する番号を付 けて発行します。例えば e3に対 して c14n1が発行される場合があります。

4.5.2 アルゴリズム

入力は 識別子発行器 I と existing identifier 、出力は新しい issued identifierです。手順は次のとおりです。

  1. マップ項目 が existing identifier に対応して 発行済み識別子マップ （ Iのもの）にあれば 、それを返します。
  2. issued identifier を、 識別子接頭辞 と 識別子カウンターの文字列値の連結で生成します。
  3. 項目 を、 existing identifier から issued identifier への対応として、 発行済み識別子マップ （ Iのもの）に追加します。
  4. 識別子カウンターを増分します。
  5. issued identifierを返します。

4.6 一次クアッドのハッシュ

ハッシュ を所与の 空白ノード について、それを含む クアッド （ データセット 内）から計算 します。一意 に識別できれ ば追加調査 は不要です。 それ以外は 4.8 N 次クアッドのハッシュ を 4.4 正規化アルゴリズムから呼び出して計算します。

4.6.1 概要

この節は非規範的です。

ノード n の一次情報が一意 か判定するため、 ハッシュ を 言及集合 Qnに割り当てま す。空白ノード nの一次ハ ッシュ hf(n)は 、 4.6 一次クアッドのハッシュ に nを渡した結果です。一意の一次ハッ シュは一意の一次情報を示します。

一貫性のため、 空白ノード識別子 （ Qn 内）はクアッドの 正規 N-Quads 直列化でプレースホルダー に置き換えます。各成分は a または zに置き換え、そ の選択は成分が n かどうかで決まります。

直列化したクアッドを コードポイント順に並べ、連結 してハッシュ します。これが nの一次ハッシュ hf(n)です。

4.6.2 例

この節は非規範的です。

例 4: 一意のハッシュ

この例は空白ノードを含むクアッドのハ ッシュを示します。それらのノードへの 言及 を含む文から一意の結果が得られます。

:p :q _:e0 .
:p :r _:e1 .
_:e0 :s :u .
_:e1 :t :u .

各空白ノード（e0 と e1）について一回ずつ、合計二 回呼び出します。参照ノード e0 で実行すると、空白ノードの置換 後に次のクアッドが得られます。

:p :q _:a .
_:a :s :u .

続いてこれらを直列化した 正規 N-Quads 形式: '<http://example.com/#p> <http://example.com/#q> _:a .\n_:a <http://example.com/#s> <http://example.com/#u> .\n', を連 結し、 ハッシュアルゴリズム （SHA-256）でハッシュすると、結果は 21d1dd5ba21f3dee9d76c0c00c260fa6f5d5d65315099e553026f4828d0dc77aです。

参照ノード e1 で二回目を実行し、次 のクアッドを得ます。

:p :r _:a .
_:a :t :u .

続いてこれらを直列化した 正規 N-Quads 形式: '<http://example.com/#p> <http://example.com/#r> _:a .\n_:a <http://example.com/#t> <http://example.com/#u> .\n', を前と同様に連結してハッシュすると、結果は 6fa0b9bdb376852b5743ff39ca4cbf7ea14d34966b2828478fbf222e7c764473です。

各ハッシュは一つの空白ノードだけを 指すため、正規化では一次クアッドのハ ッシュアルゴリズムだけを使えます。

例 5: 共有ハッシュ

この例は空白ノードを含むクアッドのハ ッシュを示します。それらのノードへの 言及 を含む文から重複する結果が得られる場合です。

_:a :p _:z .

そのハッシュは 3b26142829b8887d011d779079a243bd61ab53c3990d550320a17b59ade6ba36です。

参照ノード e1 でも同じクアッドになり 、ハッシュも同じです。

参照ノード e2 では次のクアッドを得ます。

_:z :p _:a .
_:a :r _:z .

そのハッシュは 15973d39de079913dac841ac4fa8c4781c0febfba5e83e5c6e250869587f8659です。

最後に、参照ノード e3 では次のクアッドを得ます。

_:z :p _:a .
_:z :r _:a .

そのハッシュは 7e790a99273eed1dc57e43205d37ce232252c85b26ca4a6ff74ff3b5aea7bccdです。

e2 と e3 のハッシュは一意ですが、 e0と e1 は同じハッシュです。一意 のハッシュを求めるため、 N 次クアッドのハッシュアルゴリズムで、 直接の 言及 より離れたクアッドを調べる必要があります。

4.6.3 アルゴリズム

入力は 正規化状態 と reference blank node identifier です。

  1. nquads を空の リストに初期 化し、 正規 N-Quads 形式のクアッドを保存します。
  2. リスト （ クアッド のもの）quads を、 マップ項目 （ reference blank node identifier に対応する 空白ノードからクアッドへのマップ内の項目）から取得します。
  3. 各 クアッド quad （ quads内）について：
    1. quad を 正規 N-Quads 形式 で、次の特別な規則を 使って直列化します：
      1. quad のいずれかの成分が 空白ノードなら、次のように特別な識 別子を使って直列化します：
        1. 空白ノードの既存 空白ノード識別子 が reference blank node identifier と一致すれば、 空白ノード識別子 aを使い、 それ以外は 空白ノード識別子 zを使います。
  4. nquads を Unicode コードポイント順に並べます。
  5. ハッシュ を返します。これは、 ソートして連結した nquads を ハッシュアルゴリズムに渡した結果です。

4.7 関連空白ノードのハッシュ

このアルゴリズムは ハッシュ を、 空白ノード 成分について クアッド内の位置を 考慮して生 成します。 N 次クアッドのハッシュアルゴリズム の一部と して、 言及集合内で特定の空白ノードに関連するノードの特徴を表します。

4.7.1 概要

この節は非規範的です。

identifier は 空白ノード relatedを識別し、こ のノードは クアッドの成分です。識別子と位 置情報からクアッド内の ノードの表現を作り、ハ ッシュします。まず次 から識別子を求めます。

  1. 正規発行器 （ 正規化状態内）の発行済み識別子、
  2. issuerの発行済み識別子、または
  3. N 次クアッドのハッシュアルゴリズム を relatedに適用した結果。

4.7.2 例

この節は非規範的です。

例 6: 正規識別子を割当済み

この例はクアッドの空白 ノード成分に関連ハッシ ュを生成します。成分は 目的語 の位置に あり、 正規発行器が正規識別子を発行済みです。

述語 :pと、 related が指す空白ノード e2 （正規 空白ノード識別子 c14n0を発行済 み）から、 input を o<http://example.com/#p>_:c14n0とし、ハ ッシュ 29cf7e22790bc2ed395b81b3933e5329fc7b25390486085cac31ce7252ca60faを得ます。

識別子がまだ なければ、 一次クアッドのハッシュアルゴリズムの結果を 、先頭の _:なしで使います。

4.7.3 アルゴリズム

このアルゴリズムは ハッシュ を作り、一つの 空白ノード と別のノードの関連を識別します。入力は 正規化状態、 related という空白ノード識別子、 quad、 識別子発行器 issuer、および 文字列 position です。

  1. 文字列 input を positionの値に初期化します。
  2. position が gでなければ、 <、 述語 の値（ quad内）、 > を順に inputに追加します。
  3. relatedに正規識別 子、または issuerが発行した識別子 があるなら、文字列 _:と、それに続くその識別子（正規 識別子があればそれを、なければ issuerが発行したもの）を inputに追加します。
    説明

    relatedに正規識別子が 発行済みなら、 正規発行器 （ 正規化状態内）にあります。そ れ以外は、一時的な issuer が relatedの対応を持つ可能性があります。

  4. それ以 外は、 一次クアッドのハッシュアルゴリズムに related を渡した結果を inputに追加します。
    説明

    正規識別子も一時識 別子も未発行なら、 一次クアッドのハッシュアルゴリズムで新しい識別子を作ります。

    一次クアッドのハッシュアルゴリズム は手順 3 （ 正規化アルゴリズム内）ですべてのノードにつ いて呼出済みです。実装は 一次クアッドのハッシュアルゴリズム の再実行ではなく、既存の結果の再利用を検討すべきです。

  5. ハッシュ を返します。これは input を ハッシュアルゴリズムに渡した結果です。
    説明

    得られた文字列からハッシ ュを生成します。この点は 一次クアッドのハッシュアルゴリズム が クアッド の直列化を nquads からハッシュすることと同様です。一貫性のため、 nquad 表現の identifier を使う ので、 _: という文字列が現れます。

    ログ記録

    このアルゴリズムの入力と実行結果を記録します。

4.8 N 次クアッドのハッシュ

このアルゴリズムは ハッシュ を所与の 空白ノード について、それを含む クアッド （ データセット 内）のハッシュで一 意に識別できない場 合に計算します。直接 参照するクアッド（ 言及集合）から、その集合のクアッドと 成分ノードを共有する他のクア ッドへ探索を広げます。これを 伝播経路と呼びます。一意のハッ シュが得られるまで間 接の次数を増やします。

4.8.1 概要

この節は非規範的です。

通常、グラフの二つのノードが 同値かは識別子の比較で判定し ます。識別子がなければ、グラ フ全体で同値なノードに同値な 接続を持つか調べます。これが グラフ同型 問題です。このアルゴリズムは 紙にグラフを描く考え方で扱い ます。一つ目のノードを中央に して描き、二回目に二つ目のノ ードを中央にしても同じ図を 描けるなら、両者は同値です。 つまり、特定のノードから始 めると常に同じ描き方になる決 定的な方法を定義します。異 なる二つのノードから同じ図に なれば、ノードは同値です。 ハッシュ はその特定の描き方を表し 、ノードの比較に使えます。

一次ハッシュが同じ 二つのノードには 、全体的な、つまり N次の違いを検出する追加手順が必要です。他の空白 ノードを通じて、推移的なものも含め、空白ノード n に何らかの形で接続するすべての情報を考慮します。

推移的な情報をすべて 考慮するため、関連する 言及 の経路をすべて探索して符号化します。 nから出るこの 伝播経路は 、 nに接続する各未ラベルの空白ノー ドに達します。各ノードには探索 中の経路で到達する順に一時識別 子を割り当てます。接続先に達す るためたどった言及は、関連ハッ シュで経路に符号化します。こう して、入力の識別子に依存せず、 n からすべての接続ノー ドへ達する経路を決定 的に順序付けられます。

このアルゴリズムは主正規化アルゴリ ズムと協調し、特定の空白ノードに一 意で決定的な識別子を作ります。この ハッシュ は接続するすべての情報と接続 方法を含みます。そのため、ノー ドから隣接する他の空白ノード を通る決定的な経路を作ります。

最終的に、文字列での符号化に基づく最短の 伝播経路 を選び、未ラベルの ノードへ出現順に正 規識別子を割り当て ます。この最短の符号 化経路のハッシュを nの N 次ハッシュと呼び、 n を他の空白ノードから区別します。

明確にするため、 伝播経路 を文字列 s で符号化したものが次を満たすとき、最短とします。

  1. s の長さが、他のど の伝播経路文字列 s′の長さ以下である。
  2. s と s′ の文字列長が 同じなら、 s は コードポイント順 で s′以下です。

例えば、 abc は bbcより 短く、 abcd は bcdより長いです。

以下は、 n の N 次ハッシュを最短の 伝播経路に沿って計算する方法の概要です。完全 なアルゴリズムはすべての伝播経路を検 討し、最終的に符号化後の最短経路の ハッシュ を返します。

  1. 関連ハッシュを計算。関連ハ ッシュ集合 Hn を nについて計算します。す なわち、すべての一次の 言及 （ n と別の空白ノードの間）です。未ラベ ルのノードと、正規識別子を発行済みの ラベル付きノードの両方を含みます。
  2. 言及を探索する。関連ハ ッシュ x （ Hn内）が与え られたら、 x をハッシュ対象データ Dnに記録します。各空 白ノードについて、 言及 （関連ハッシュが x のもの）を通じて到達できるなら、既に識別子を受け取ったかを調べます。
    1. ラベル付きノードの識別子を記録。空白ノー ドに識別子 があれば、 Dn に記録します。各 言及 の関連ハッシュが xであるたびに一 度記録します。 Hn の次の関連ハッシュに進み、 手順 2を繰り返します。
    2. 未ラベルのノードに一時識別子を割り当てて記録。伝播経路で到 達する順に各ノ ードへ一時識別 子を割り当て、 Dn に重複も含めて記録します。同 じ順に各ノードを再帰リスト Rn(x) に追加します（重複は省く）。
    3. 新たにラベル付けしたノードについて再帰する。 各 ni （ Rn(x) 内）について
      1. その識別子を Dnに記録します
      2. < r(i) > を Dn に追加します。 r(i) は 手順 1に戻 り、 n を niに置き換えて得られるハッシュ対象データです。
  3. n の N次ハッシュを計算。 Dn をハッシュし、 N次ハッシュ（ nのもの） 、すなわち hN(n)を返します。 更新済み発行器 In も返します。これは nにつながる全未ラベルノードへ一時識別子を割り当て済みです。

上述の 手順 2.3のとおり、 HN は探 索中の 伝播経路 で初めて到達した未ラベルノー ドに再帰します。これは経路を n から一時識別子を受け取るノード ni へ移動することと 考えられます。 niで別の未ラ ベルノード nj を発見すれば、 さらに再帰しま す。この再帰は 伝播経路 、すなわち n から nj へ、 niを経由する経路をたどります。

再帰ハッシュ r(i) は、返される ハッシュ であり、 ノード ni への再帰を、 hN(n)の計算中に完了 した結果です。 hN(n) が Dnのハッシュで あるように、 ni での再帰のハッシュ対象データを Diとします。 したがって r(i) = h(Di)です。各関 連ハッシュ x ∈ Hnについて、 Rn(x) を、アルゴリズムが再帰する 再帰リスト と呼び ます。

5. 直列化

この節では、直列化された [N-Quads] 表現を 正規化データセットから作成する手順を説明します。

直列化された正規形式 （ 正規化データセット のもの）は N-Quads 文書 [N-QUADS] です。各 クアッド を 正規化データセット から取り出し、 正規 N-Quads 形式で表 して コードポイント順に並べ、連結して作成します。（各 正規 N-Quads 文は改行で終わるため、連 結時に区切りを追加する必要はあり ません。）結果の文書のメディア型は application/n-quadsです。 これは C. N-Quads のインターネットメディア型、ファイル拡張子、Macintosh ファイル型 （[N-QUADS]）で説明されています。

正規 N-Quads 形式でクアッドを直 列化するとき、 空白ノード である成分は対応する正規ラベルを使って直列化しなければなりません（MUST ）。 各 空白ノード のラベルは 発行済み識別子マップ （ 正規化データセットの構成要素）から得ます。

6. プライバシー上の考慮事項

この節は非規範的です。

正規化アルゴリズムの性質上、出力である正規ラベル とクアッドの整列順序は入力データセットと本質的に 相関します。特に個人情報を含むデータセットでは問 題になり得ます。例えば、プライバシー保護のために 正規化データセット から情報を削除しても、第三者がそのデータ セットを分析して省略されたデータを推測で きる可能性があります。入力と出力の相関を 解く必要があれば、正規化出力に適切な後処 理を行うべきです。本仕様は追加処理を容易 にするよう設計されていますが、具体的な詳 細は本仕様に基づく他の仕様が提供する責任 を負います。このような後処理の詳細は、 選択的開示 （ 検証可能なクレデンシャルのデータ完全性 1.0 [VC-DATA-INTEGRITY]）を参照し てください。

7. セキュリティ上の考慮事項

この節は非規範的です。

7.1 データセット・ポイズニング

この節は非規範的です。

正規化アルゴリズムは、各空白ノードが自身の正 規識別子を正しく得るよう、接続された情報のあ らゆる差異を調べます。攻撃者はこの処理を悪用 し、正規化に大量の計算時間がかかると分かって いながら、有用な情報を表さない、または不必要 に複雑な方法で情報を表すデータセットを構築で きます。実装者には、問題のある入力の正規化を 既定で中止する緩和策の追加が期待されます。

推奨される緩和策には、次のものがありますが、これらに限定されません。

  • 設定可能なタイムアウトを提供し、実装の 一般的な用途に適した既定値を設けること
  • アルゴリズムの手順、特に再帰手順 と長いリストの順列について、反復 回数の上限を設定可能にすること

また、アルゴリズムの実装を利用するソフトウェアは、 スキーマ検証のベストプラクティスを用いてアプリケー ションの要件を満たさないデータを拒否し、無用な汚染 データセットの処理を防げます。ただし、これらの緩和 策はアプリケーション固有であり、正規化アルゴリズ ム自体の実装者に直接適用されるものではありません。

7.2 安全でないハッシュアルゴリズム

この節は非規範的です。

既定の ハッシュアルゴリズム （ RDFC-1.0 が使用）は将来安全でなくなる可能性があり ます。その対策として、このアルゴリズムと 実装はパラメーターにより別のハッシュ関数 を使用でき、正規化アルゴリズム自体の変更 は不要です。ただし別のハッシュアルゴリズ ムを使うと一般に結果も異なります。本仕様 を利用するアプリケーションは、代替ハッシ ュ関数の利点と欠点を慎重に比較すべきです。

注

内部ハッシュ値を公開せず、正規化アルゴリズム が一次ハッシュの衝突に対処するよう設計され ていることで、既定のハッシュアルゴリズムが安 全でなくなった場合の影響を緩和しています。

A. N-Quads の正規形式

この節はレイアウトを完全に規定した N-Quads の正規形式を定義します。言語の文法は変更しません。

正規 N-Quads は 正規 N-Triples （[N-TRIPLES]）を更新 、拡張し、 graphLabelを含めます。

N-Quads 構文 [N-QUADS] は RDF データの表現とレイアウトに選択肢を認めますが、正規形式は各クアッドに一意の構文表現を与えます。該当する生成規則で表現を選べる場合、各コードポイントは UCHAR、 ECHAR、符号化しない文字のいずれ か一つだけで表します。各ク アッド全体を指定された空 白とともに一行に表します。

正規 N-Quads はレイアウトに次の追加制約を課します。

  • 空白は MUST NOT の要件として、 subject、 predicate、 object、 graphLabelの直後以外では使用して はなりません。それぞれ MUST の要件として単一の空白文字（コードポイント U+0020）である必要があります。
  • リテラル のデー タ型が http://www.w3.org/2001/XMLSchema#string である場合、MUST NOT の要件としてデータ型 IRI 部分を リテラルに使用 せず、 STRING_LITERAL_QUOTEだけで表します。
  • HEX はMUST の要件として数字（[0-9]）と大文字（[A-F]）のみを使用しなければなりません。
  • STRING_LITERAL_QUOTEの中では：
    • 文字 BS （後退、コードポイント U+0008）、 HT （水平タブ、 U+0009）、 LF （改行、 U+000A）、 FF （改ページ、 U+000C）、 CR （復帰、 U+000D）、 " （引用符、 U+0022）、 \ （逆斜線、 U+005C）は MUST の要件として ECHARで符号化しなければなりません。
    • U+0000 ～ U+0007の文字、 VT （垂直タブ、コードポイント U+000B） 、 U+000E ～ U+001Fの文字、 DEL （削除、 U+007F）、 および Char 生成規則（[XML11]）に一致しない文字は、 MUST の要件として UCHAR で、小文字の \u と 4 個の HEXを使って表さなければなりません。
    • ECHAR または UCHAR による表現が要求されないすべての文字は、MUST の要件として本来の [UNICODE] 表現で表さなければなりません。
  • トークン EOL はMUST の要件として単一の LF （改行、コードポイント U+000A）でなければなりません。
  • 末尾の EOL はMUST の要件として付けなければなりません。

B. URDNA2015

この節は非規範的です。

RDF データセット正規化 [CCG-RDC-FINAL] は「汎用 RDF データセット正規化アルゴリズム 2015」（URDNA2015）を記述 していま す。これは RDFC-1.0と本質的に同じアルゴリズムであり、 URDNA2015 の実装は一般に本仕様と互換性 があるはずです。わずかな変更は N-Quads の正規形式 にあり、一部の制御文字 が以前はエスケープせ ずに表されていました。 A. N-Quads の正規形式 で定義するアルゴリズムの版は、 単純リテラル の表 現と、 STRING_LITERAL_QUOTE 内で ECHARにより符号化する文字を明確にしています。

C. URGNA2012

この節は非規範的です。

このアルゴリズムの以前の版は少数の環境で導入されています。識別のため、そのアルゴリズムを「汎用 RDF グラフ正規化アルゴリズム 2012」（URGNA2012）と呼びます。ここで述べたアルゴ リズムとは次の点で異なります。

  • 4.6 一次クアッドのハッシュでは、 グラフ名 の位置で クアッドに空白ノードを使 用した場合、特別な 空白ノード識別子 gを zの代わりに使って値を直列化していました。
  • 4.7 関連空白ノードのハッシュでは、 述語 の値を < と >で囲まず、区切り文字を使 用していませんでした。
  • 4.8 N 次クアッドのハッシュでは、 position パラメー ターを 関連空白ノードのハッシュアルゴリズム に渡す代わりに、 direction パラメーターとしてモ デル化していました。値 pは property を表し、関連空白ノードが 主語 の場合に使い、値 rは reverse または reference を表し、関連空白ノードが 目的語の場合に使いました。 URGNA2012 はデータセットではなくグ ラフのみを正規化したため、 グラフ名 の位置は使いませんでした。
  • 4.8 N 次クアッドのハッシュでは、 Hn を次のように構築していました：
    1. 各 quad （ quads内）について：
      1. もし quadの subject が 空白ノード であ り、 identifierと一致しないなら、 hash を 関連空白ノードのハッシュアルゴリズムの結果に設定 します。渡す 空白ノード識別子 は subject のもので、 relatedとし、 quad、 issuer、および p を positionとして渡します。
      2. それ以外の場合、もし quadの object が 空白ノード であ り、 identifierと一致しないなら、 hash を 関連空白ノードのハッシュアルゴリズムの結果に設定 します。渡す 空白ノード識別子 は object のもので、 relatedとし、 quad、 issuer、および r を positionとして渡します。
      3. それ以外の場合、次のクアッドに進みます。
      4. hash から、一致した要素の 空白ノード識別子 （ subject または object）への写像を Hnに追加し、必要に応じてエ ントリーを作成します。

E. 2022 年 11 月 24 日の初回公開作業草案からの変更

この節は非規範的です。

  • アルゴリズムと例を変更し、 空白ノード識別子に一貫して xyz 形式を使い、 _:xyzは使わないようにしました。議論は Issue 46 を参照してください。
  • 4.6 一次クアッドのハッシュ を簡略化し、既存の実装で使用していなかった simple フラグを削除 しました。当 初は、割り当 て済みの正規 空白ノード識別子があ れば、 _:a や _:zの代わりに使用する設計でした 。これは関連ハッシュアルゴリ ズムでの使い方と同様ですが、 実装が進む前にこの記述が仕様 に入ることはありませんでした 。そのためハッシュは変化せず、 simple フラグに基づいてこのアルゴリズム を呼び出すループは不要です。議論は Issue 23 を参照してください。
  • N-Quads の正規形式の定義を追加しました。最終的には [N-Quads] の更新時に同仕様への参照とする予定です。 N-Quads の正規形式 は 4.6 一次クアッドのハッシュで使用します。
  • Issue 15 の問題マーカーを 4.4 正規化アルゴリズムから削 除し、 リテラル である クアッド の構成要素は正規化されず、構文表現の 異なる二つのリテラルは別のリソースの ままであるという注記を追加しました。
  • 空白ノード識別子の 記述方法を変更し（ Issue 46参照）、直列化に よって生じる先頭の _: を通常は省略しました。アルゴ リズム内では引き続き必要です が、識別子そのものと直列化形 式の違いを明確にしました。
  • アルゴリズム名を URDNA2015 から RDFC-1.0に変更しました。
  • 用語 normalized dataset を 正規化データセットに変更しまし た。これは 入力データセット、 入力空白ノード識別子マップ、 発行済み識別子マップから構成されます。
