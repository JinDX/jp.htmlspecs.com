概要

このCSSモジュールは、アニメーション画像の描画を制御する機能を提案します。

CSSは、構造化された文書（HTMLやXMLなど）の 画面上、紙上などでの描画を記述するための言語です。

1. はじめに

この節は非規範的です。

アニメーション画像（[GIF]、[PNG]、[WebP] などで実現される）は、 Web 上で広く使用されています。 デフォルトでは、ユーザーエージェントはこれらの画像を自動再生します。 これはユーザーに不快感を与える可能性があり、 特に単一のページに複数の画像がある場合（画像ギャラリーなど）には顕著で、 WCAG 2.2 §  達成 基準 2.2.2 一時停止、停止、非表示に違反します。 現在、 サイトの作成者はこれを制御できません。

そのため、ユーザーにはこのようなアニメーションを制御したいという要望があります。 しかし、用途が多様であるため、 ユースケースや求められるUI、ユーザー エクスペリエンスには幅広い違いがあり、 これをユーザーエージェントの自動機能やオプトイン機能にするだけでは十分では ありません。

ユーザーに最適なエクスペリエンスを提供するには、 Web サイトが再生エクスペリエンスを制御する必要があります。 それも、アニメーション画像の用途ごとに個別に制御する必要があります。

この仕様では、CSS プロパティ（image-animation） と疑似クラス（:animated-image）を提案し、 作成者がアニメーションを制御できるようにするとともに、 この制御と、それに関連付けたい任意のUIを 対象となる要素に適用できるようにします。

動機や検討された代替案についてさらに詳しく知るには、 別途管理されている 解説文書 および、このトピックに関するプレゼンテーション も参照してください。

この仕様のいかなる規定も、ユーザーエージェントがユーザーに 画像アニメーションを全体的に制御する設定を提供することを妨げません。 たとえば、すべてのアニメーション画像を静止画像に変えるオプションなどです。

2. 画像アニメーションの制御: image-animation プロパティ

名前: image-animation
値: normal | paused | stopped | running
初期値: normal
適用対象: 宣言的 画像
継承: はい
パーセンテージ: 該当なし
算出値: 指定どおり
正規順序: 文法に従う
アニメーションの種類: 離散

このプロパティを使用すると、作成者は アニメーション画像を アニメーション状態で表示するか、 一時停止するかを制御できます。

要素に複数の宣言的画像が含まれる場合 （たとえば、複数の背景画像やボーダー画像を持つ要素、 または画像を表すホスト言語の置換要素で、 CSS によって1つ以上の画像も関連付けられているもの）、 その要素におけるこのプロパティの算出値は、それらすべてに影響します。

注記: したがって、要素の一部の画像の アニメーションだけを一時停止し、 同じ要素のほかの画像のアニメーションを実行し続けることはできません。

アニメーションしない画像の場合、 このプロパティの値による影響はありません。 また、このプロパティは動画にもプログラムによる画像にも 影響しません。

このプロパティをルート要素に適用すると、 背景画像に対するその効果はキャンバス の背景に伝播します。

注記: 互換性上の理由から、 background プロパティは、ルート要素からだけでなく、 HTML の body 要素からも伝播します。 しかし、image-animation のような新しいプロパティは、ルート要素からのみ 伝播します。 このプロパティを body に設定しても伝播しません。 background がそこに設定されている場合でも同様です。

normal
アニメーション 画像のアニメーションは、 画像形式とホスト言語によって決定されるとおり、通常どおり実行されます。

さらに、 同じアニメーション画像で、 同じ絶対 URL、 同じ画像データを持ち、 image-animation の算出値が normal' であるものは、 グループとして同じタイムラインに同期して描画されなければなりません。 そのタイムラインは、グループへの最も古い追加時点に開始します。

注記: 上記の要件は、[HTML] の描画に関する 期待事項であるHTML § 15.4.2 画像に基づいています。 [HTML] は、 一般にユーザーエージェントに対して文書を特定の方法で表示することを要求しておらず、 したがって、上記の動作を規範的には要求していません。 この仕様ではそれを要求します。

stopped
アニメーション画像は、 静止 画像であるかのように描画されます。 ユーザーエージェントは、画像に含まれるいかなるアニメーションも実行してはなりません。 画像にカバー フレームが含まれる場合、 ユーザーエージェントはそれを使用しなければなりません。 それ以外の場合は、 アニメーションの初期状態における画像を表示しなければなりません。
paused
ユーザーエージェントは、 アニメーション 画像に含まれるアニメーションを実行してはならず、 この値が適用され始めたときの状態のまま、 画像を表示し続けなければなりません。 これにより、実質的にアニメーションが一時停止されます。

この値が適用される前に アニメーションが再生されていなかった場合、 動作はstoppedと同じです。

running
normalと同様に、 アニメーション 画像のアニメーションは、 画像形式とホスト言語によって決定されるとおり、通常どおり実行されます。

ただし、 アニメーションのタイムラインは要素ごとに区切られます。 単一の要素に含まれるすべての画像のうち、 image-animation の算出値が running であるものについては、 同じアニメーション画像で、 同じ絶対 URL と同じ画像データを持つものは、 グループとして同じタイムラインに同期して描画されなければなりません。 このタイムラインは、ほかの要素にある画像のタイムラインとは区別されます。

算出値が running の間に画像が要素へ追加された場合、 タイムラインはグループへの最も古い追加時点に開始します。

要素が作成された場合、または以前に display: none に設定されていた要素が表示されるようになった場合、 画像がすでに追加され、image-animation がすでに running に設定されていれば、 タイムラインは、その要素がレイアウトに含まれた時点で開始します。

このプロパティを別の値から running に切り替えた場合、 このタイムラインの開始時点は、 アニメーションが切り替え時に表示されていた状態から 続行するように設定されます。

作成者は、このプロパティを使用して必須ではない画像アニメーションを抑制できます。 これは、prefers-reduced-motion メディア特性で表明されたユーザー設定に応じて行えます。 ここでは、CSS に基づく画像を静止状態にする一方、 img 要素のアニメーションは実行し続けます。 
:root { /* 継承によって文書全体に伝播する */
  image-animation: paused;
}
img {
  image-animation: normal;
}
ある HTML ページには複数の img 要素があり、 それぞれが同じ画像のインスタンスを表示しています。 （絶対 URL と画像データが同じ）ものであり、 すべてに image-animation: normal が指定されています。

そのうちの1つの要素で、image-animation プロパティを 一時的に paused に切り替えると、 その画像のアニメーションが一時停止します。 ほかの画像は影響を受けず、 アニメーションを実行し続けます。

image-animation プロパティが paused である要素を、 後で running に変更します。 その時点で、その画像のアニメーションは再開されますが、 ほかの画像がタイムライン上のどこまで進んでいるかには関係なく再開されるため、 同期が取れなくなります。

さらにその後、その要素の image-animation プロパティを normal に変更します。 その時点で、画像のアニメーションは即座に同期状態へ戻り、 ほかのインスタンスと同期します。

image-animation プロパティは、ラスター画像 形式だけでなく、 ベクター画像にも影響します。 SVG も含まれます（[SVG2] を参照）。 ただし、これは画像として読み込まれた独立した SVG リソースにのみ適用され、 HTML 文書にインラインで埋め込まれた svg 要素は含まれません。 （ただし、このプロパティを svg 要素に設定した場合、 このプロパティは継承され、 SVG の アニメーションする 宣言的画像のうち、 image 要素を介して読み込まれたものにも影響します。）

3. アニメーション画像の識別: :animated-image 疑似クラス

:animated-image 疑似クラスは、宣言的画像を表す要素のうち、 アニメーション画像が 読み込まれている要素にマッチします。 animated-image 疑似クラスがマッチするには、 画像がアニメーション可能な形式であるだけでなく、 実際にアニメーションする画像でなければなりません。

宣言的画像を表さない要素には、 animated-image 疑似クラスは決してマッチしません。

作成者はこの疑似クラスを使用して、 一時停止中の画像をユーザーが再生できるようにする ユーザーインターフェイスを選択的に提供できます。

この単純な例では、 アニメーション可能な画像は最初に一時停止され、 それらにフィルターが適用されます。 これにより、画像はくすんだ灰色がかった外観になります。 画像にポインターを重ねるか、フォーカスを合わせると、 フィルターが解除され、 画像の再生が可能になります。

img:animated-image {
  image-animation: paused;
  filter: grayscale(10%) contrast(50%) brightness(80%);
}
img:animated-image:hover,
img:animated-image:focus {
  filter: none;
  image-animation: running;
}
画像アニメーションを制御するUIを構築する作成者は、 キーボード利用者のニーズを 考慮することが重要です。 また、操作がマウスのみに依存しないようにする必要があります。
上記の例では、 画像にポインターを重ねた場合だけでなく、 フォーカスを合わせた場合にも再生が開始されます。 これを完全に機能させるには、 アニメーション可能な画像をフォーカス可能にする必要があります。 これは、たとえば 次のコード片で実現できます。 
function setImageFocusability(event) {
  var img = event.target;
  if (img.matches(":animated-image") {
    img.tabIndex = 0;
  } else {
    img.removeAttribute("tabindex");
  }
}
document.querySelectorAll("img").forEach( (i) => {
  setImageFocusability({target: i });
  i.addEventListener('load', setImageFocusability);
  i.addEventListener('error', setImageFocusability);
});

:animated-image がマッチするかどうかは、 画像の現在の再生状態にも、 image-animation プロパティの値にも影響されません。 ただし、ユーザーエージェントの設定によって画像アニメーションが全体的に無効化されている場合、 その設定が有効な間は、 そのユーザーエージェントは、本来アニメーションするものの再生が抑制されている画像を 静止画像として扱い、 :animated-image にマッチしないようにしてもかまいません。

画像アニメーションを無効化する全体設定を持つユーザーエージェントは、 ユーザビリティとプライバシーの間でトレードオフに直面します。 :animated-image の主な機能は、作成者が 画像アニメーションの UI コントロールを アニメーション可能な画像だけに適用できるようにすることなので、 アニメーションが抑制されている画像には :animated-image がマッチしない方が 作成者にとって望ましいことになります。 しかし、これはフィンガープリンティングの手段として利用される可能性があります。 アニメーション可能であることが分かっている画像を読み込み、 :animated-image が マッチするかどうかを調べることで、 この設定が有効になっているかを判別できます。 逆に、 ユーザーエージェントの設定によってアニメーションが抑制されている場合でも、 :animated-image が アニメーション可能な画像にマッチするようにして、この問題を緩和すると、 プライバシーは保護されますが、 作成者が画像アニメーションを制御するために導入した UI 要素が、 制御すべきアニメーションのない画像にも表示される可能性があります。

4. 用語

静止画像
単一のフレームを 最終的な閲覧体験として表示することを意図した画像です。

JPEG 画像は静止 画像です。

アニメーション画像
複数のフレームを 最終的な閲覧体験の一部として順番に表示することを意図した画像です。 ループする場合もありますが、必須ではありません。

アニメーション PNG 画像や、 アニメーションする[GIF] 画像は、 アニメーション 画像です。

プログレッシブレンダリングやマルチパス読み込みに対応しているだけでは、 その画像はアニメーション画像とはみなされません。

宣言的 画像
ホスト言語の置換要素であり、 静止画像 またはアニメーション画像を表し、 動画やプログラムによる 画像は除外されます。 または、CSS によって文書の描画に挿入される画像です。

HTML の img [HTML] 要素は、 picture 要素の中に入れ子になっている場合も含まれます。 また、HTML の object [HTML] 要素が 画像を表す場合や、 image [SVG2] 要素も 宣言的 画像です。 background-image や border-image などのプロパティ、 またはcontent プロパティによって挿入される画像も同様です。

HTML の ポスターフレームを表している場合（その場合に限る）、 video 要素は 宣言的画像とみなされます。

動画
動画を表すホスト言語の置換要素であり、 通常は音声を伴いますが、必須ではありません。 また通常は、対話的なコントロール （再生、一時停止、シーク、音量調整、全画面表示など）とともに提示されますが、必須ではありません。 キャプションや字幕を伴う場合もありますが、必須ではありません。

注記: 概念的な観点から、かつ ファイル形式のみに基づいて考えると、 動画とアニメーション画像には相当な 重なりがあり、 原理的に両者を必ずしも区別できるわけではありません。 ここでの区別は、作成者の意図に基づきます。 その意図は、文書内で選択された要素によって表されます。

HTML の video [HTML] 要素は、 動画を表します。

両方の用途をサポートするユーザーエージェントを想定すると、 同じ video/mp4 ファイルでも、 video 要素を通じて表示される場合は、 動画とみなされ、 CSS の background-image として使用される場合は、 宣言的 画像とみなされます。
プログラムによる 画像
外部リソースから読み込まれるのではなく、 ホスト言語の API を介してプログラムによって作成される画像です。

HTML の canvas [HTML] 要素は、 プログラムによる 画像を表します。

カバーフレーム
一部のアニメーション画像 形式では、 画像の作成者が 静止画像を指定できます。 この文書では、それをカバーフレームと呼びます。 これは、アニメーションが実行されていないときに表示されるものであり、 アニメーションの初期状態とは異なります。

5. アクセシビリティに関する考慮事項

この節は非規範的です。
  • この仕様で導入される機能により、作成者は、 そうしなければ違反となる WCAG 2.2 §  達成 基準 2.2.2 一時停止、停止、非表示への対応が可能になります。
  • Web ページにはすでにアニメーション画像を含めることができ、 適切な alt テキストを提供することがすでに期待されています。 アニメーションの一時停止や再開に対応するための変更は、想定も必要もされていません。 たとえば、 「落ちてくる金床に押しつぶされる漫画のコヨーテ」、 「かわいく踊るハムスター」、 「工事中」、 「回転する読み込みインジケーター」 といった説明は、 アニメーションが実行されているかどうかにかかわらず、同様に適切で内容を伝えます。
  • 現在、スクリーンリーダーは通常、アニメーション画像を 非アニメーション画像と区別して読み上げることはありません。 ただし、望ましいと判断されれば、アクセシビリティツリーを拡張してこの情報を公開できます。 同様に、一時停止中の画像と再生中の画像を異なる方法で読み上げることも想定されていません。 ただし、望ましいと判断されれば、アクセシビリティツリーを拡張してこの情報を公開できます。
  • § 3 アニメーション画像の識別: :animated-image 疑似クラスで説明したように、 画像アニメーションを制御するUIを構築する作成者は、 アクセシブルなUIを構築するために、 通常必要となる予防措置を講じる必要があります。 CSS では要素を直接フォーカス可能にすることができないため、 適切なキーボードナビゲーションには、要素の属性も設定する必要があります。 代替案としては、 :animated-image 疑似クラスがマッチする要素に 作成者独自のUIを構築できるようにする代わりに、またはそれに加えて、 作成者がユーザーエージェントに指示して、 適切な場合にユーザーエージェント自身がUIを 提供するようにする方法も考えられます。

    たとえば、controlled という追加の値を image-animation プロパティに定義できます。 この値が指定された場合、 最初は画像のアニメーションが実行されず、 paused が指定されたかのようになります。 さらに、 基になる要素が画像を表しており、 （つまり、CSS によって読み込まれた画像ではなく） その画像が実際にアニメーションする画像である場合、 ユーザーエージェントは、ユーザーが アニメーションを再生および一時停止できるUIを提供し、 その要素をフォーカス可能にもします。

    必要であれば、この機能はこの仕様の後のバージョンに追加できます。 しかし、 作成者がこれを広く使用するかどうかは不確かです。 作成者は多くの場合、自分のサイトに合わせて特別に設計した UIコントロールを好むためです。 そのため、この仕様では、 このような解決策の複雑さについての検討を、 作成者の需要が確認されるまで延期することにしました。

6. プライバシーに関する 考慮事項

この節は非規範的です。

image-animation プロパティは、オリジンをまたいで画像 アニメーションを制御できるようにしますが、 その画像が実際にアニメーション可能かどうかに関する情報は漏洩しません。 算出値はこの情報によって変化しません。 running 値は、アニメーション画像と 静止画像とで 視覚的に異なる効果を持ちますが、これらの違いはいずれもページ自体からは観測できません。

しかし、:animated-image 疑似クラスは、 要素が表す宣言的 画像がアニメーション画像か静止画像かを明らかにします。 これは、ページが通常はオリジンをまたいで知ることのできない情報です。 CORS によってこれを制限することもできますが、 この仕様ではそのような制限を課さないことにしました。 理由は次のとおりです。

  • この情報から得られる、すでに知られていない新たな情報は多くありません。

    • 対象 URL に画像が存在するかどうか自体が、 ユーザーに関する重要な情報 （たとえば、特定のドメインにログインしているかどうか）を明らかにする可能性があります。 しかし、これは画像の寸法からすでに判別可能であり、 アニメーション可能かどうかは、このリスクを実質的に増大させません。

    • 実際には、同じ URL から 静止画像とアニメーション画像の両方を配信し、 ユーザーに依存する何らかの非公開情報に基づいて配信する画像を選択し、 それによってその情報が漏洩するようなサイトが設計される可能性は非常に低いと考えられます。

  • 動画については、同様の情報がすでに共有されています。 HTML の video 要素は、クロスオリジンの動画であっても再生時間を公開します。 静止画像は、再生時間が 0 のアニメーション画像の特殊な場合と考えることもできるため、 この情報を公開することは類似したものといえます。

  • <video> 要素で画像を使用できるようにする提案があります。 これが実装されれば、状況が単に類似しているだけでなく、 画像がアニメーションするかどうかは、いずれにせよオリジンをまたいですでに判別可能になることを意味します。

さらに、ユーザーエージェントが画像アニメーションを抑制する設定を提供する場合、 その設定と:animated-image 疑似クラスとの相互作用は、 フィンガープリンティングに利用できる情報源となる可能性があります。 これについては、対応する節で説明しています。
