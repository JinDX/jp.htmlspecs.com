概要

このモジュールは、コンテンツに基づく「内在」サイズとコンテキストに基づく「外在」サイズを表すキーワードによって CSS のサイズ指定プロパティを拡張し、 CSS がコンテンツに適合するボックスや、特定のレイアウトコンテキストに 適合するボックスをより簡単に記述できるようにします。これは CSS Sizing Level 3 に対する差分仕様です。

CSS は、構造化文書 （HTML や XML など）の画面や紙などにおける レンダリングを記述するための言語です。

1.1. モジュール間の相互作用

このモジュールは、width、height、min-width、min-height、max-width、max-height、および column-width の機能を拡張します。これらは [CSS2] の第10章および [CSS3COL] で定義されています。

1.2. 値の定義

この仕様は、[CSS2] の CSS プロパティ定義規約に従い、 [CSS-VALUES-3] の 値定義構文を使用します。 この仕様で定義されていない値型は、CSS Values & Units [CSS-VALUES-3] で定義されています。 他の CSS モジュールと組み合わせることで、これらの値型の定義が拡張される場合があります。

各定義に列挙されているプロパティ固有の値に加えて、 この仕様で定義されているすべてのプロパティは、 プロパティ値として CSS 全体キーワードも受け入れます。 読みやすさのため、これらは明示的には繰り返していません。

名前: size
値: <'width'> <'height'>?
初期値: auto

継承: 個々のプロパティを参照

size プロパティは、一括指定プロパティであり、 width と height を1つの宣言で設定します。 2番目の値が省略された場合、 1番目の値がコピーされます。

size プロパティは、互換性問題や @page との競合を避けるため、 CSSOM の 推奨される 一括指定順序から除外する必要があります。

3.2. 新しいサイズ指定値: contain、fit-content()、および calc-size() 値

CSS Sizing 3 § 3.2 サイズ指定値: <length-percentage>、auto | none、min-content、max-content、および fit-content() 値

Level 4 では、 contain、fit-content()、および calc-size() 値を サイズ指定プロパティで使用できるようになり、 それによって <box-size> 生成規則を次のように拡張します:

<box-size> = <length-percentage> | stretch | contain | min-content | max-content | fit-content | fit-content() | calc-size()
名前: width, height, min-width, min-height, max-width, max-height
新しい値: contain | fit-content(<length-percentage [0,∞]>)
fit-content(<length-percentage [0,∞]>)
fit-content の式を、 利用可能な空間を指定された引数に置き換えて使用します。 すなわち min(max-content, max(min-content, <length-percentage>)) です。ここで、<length-percentage> 引数は、 単独で現れる <length-percentage> 値の場合とまったく同じように解決されます。

負の <length-percentage> 値は無効です。

4. アスペクト比

画像には多くの場合、自然アスペクト比があり、 CSS レイアウトアルゴリズムは要素のサイズを変更する際に それを維持しようとします。

aspect-ratio プロパティを使用すると、 非置換要素に対してこの動作を指定し、 置換要素の実効アスペクト比を変更できます。

この節の詳細については まだ作業中です。 ここで指定されている動作のいずれかによって、 置換要素で 優先アスペクト比を持つものが、 この仕様が適用されていない状態で CSS2、 Flex Layout、 および Grid Layout の仕様を組み合わせた要件の下での動作と異なる動作をする場合、 それはエラーであり、CSSWG に報告する必要があります。 未解決の aspect-ratio イシューの一覧があります。

4.4. 最小/最大サイズの転送

どちらかの軸 （origin 軸）におけるサイズ指定制約は、 優先アスペクト比を介して転送され、 もう一方の軸（destination 軸）にある 不定の 最小、最大、または 優先サイズに 次のように適用されます:

  • まず、確定した 最小サイズは、 origin 軸から destination 軸へ 変換されて転送されます。 この転送された最小値は、 destination 軸にある 確定した 優先または 最大サイズを 上限とします。

  • 次に、確定した 最大サイズは、 origin から destination へ 変換されて転送されます。 この転送された最大値は、 destination 軸にある 確定した 優先または 最小サイズ、 および存在する場合は転送された最小値を 下限とします。

注: したがって、確定サイズは転送された制約によって まったく影響を受けません。 また、転送された最小値によって要素が確定した優先/最大サイズを超えることはなく、 転送された最大値によって要素がその優先/最小サイズに違反することもありません。

注: 基本原則は、サイズ指定制約が アスペクト比を介して反対側へ転送され、 影響を受ける軸に明示的に指定されたサイズに違反しない範囲で 可能な限りアスペクト比を維持することです。 （これは CSS2 第10.4節の 制約表の内容を決定した原則です。）

次の例では: 
<div id=container style="height: 100px; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">コンテンツ</div>
</div>

#item の高さは確定したコンテナーに対して解決されるパーセント値であるため、 項目の幅は、その内在サイズへの寄与についても最終レイアウトについても 100px に解決され、 したがってコンテナーも幅 100px になります。

<div id=container style="height: auto; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">コンテンツ</div>

5.2.1. 最後に記憶されたサイズ

サイズ包含は、ページを効率的にレンダリングできるようにするうえで非常に有用であり、 要素のレンダリング変更の結果として発生し得る レイアウト処理の範囲を制限します。 しかし、作者にとっては非常に制約が強く、 要素のサイズがどうなるかを正しく予測する必要があります。 この予測が少しでも誤っていると、 見苦しいスクロールバーや、意図せず隠されたコンテンツが生じる可能性があります。

contain-intrinsic-size の auto キーワードは中間的な選択肢を提供します: 要素が一度でも 非サイズ包含状態になった場合、 この値によって要素はそのサイズ （通常どおりレイアウトによって計算されたもの）を記憶します。 その後、要素が サイズ包含を得た場合、 記憶されたサイズを使用し、 サイズ包含の性能上の利点を提供しつつ、 コンテンツに対しておそらく正確にサイズ指定されます。

ResizeObserver の対象になれる要素のみが、最後に 記憶されたサイズを持つことができます。

要素の 最後に記憶されたサイズは、 次のように決定されます:

  • ResizeObserver イベントが決定され配送される時点で、 要素の contain-intrinsic-size プロパティに auto キーワードがあり、 ResizeObserver の対象になれるものの、 サイズ包含を持たない場合、 その 主ボックスの現在の内部寸法を 最後に 記憶されたサイズとして記録します。

  • ResizeObserver イベントが決定され配送される時点で、 要素が 最後に記憶されたサイズを持つ一方、 contain-intrinsic-size プロパティに auto キーワードを持たない場合、 その 最後に記憶されたサイズを削除します。

注: 最後に記憶されたサイズは、 要素によって生成された特定のボックスではなく、 要素に付随する状態です。 要素が contain-intrinsic-size プロパティに auto キーワードを保持している限り、 display: none への変更またはそこからの変更のような場合でも、 最後に記憶されたサイズを保持します。

5.2.2. overflow: auto との相互作用

contain-intrinsic-size プロパティは、 作者が要素のコンテンツをどの程度の大きさと想定しているかの推定値を提供しますが、 この推定値は実際のコンテンツではなく、 ユーザーに表示する必要があるものを表すわけでもありません。 したがって、overflow: auto を持つ要素は、 contain-intrinsic-size の結果として スクロールバーを生成してはなりません。

しかし、contain-intrinsic-size が、 そのサイズの実際のコンテンツを含んでいれば要素がスクロールバーを生成するほど 十分に大きなサイズを示している場合、 その要素はそのような仮想的なコンテンツに従って スクロールバーを生成したかのようにサイズ指定されなければなりません。

次のコード例では: 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  overflow: auto;
}

要素は最終的に幅 100px、高さ 100px になります: contain-intrinsic-size が max-content 幅と、 高さも提供します。

その後、要素に高さ 150px のコンテンツが入った場合、 垂直スクロールバーが表示されます。 スクロールバーがオーバーレイでない場合、 その 100px の幅の一部を占有し、 コンテンツが流し込まれるために残る量はより小さくなります （通常は約 84px）。 （CSS Overflow 3 § 4 スクロールバーとレイアウトを参照。）

これにより、コンテンツに利用可能な水平空間が 100px 未満になったとしても、 contain-intrinsic-size が 100px の幅を示すという理由だけで、 水平スクロールバーが生成されることはありません。 これは、実際のコンテンツに改行不能なものがあり、 残りの空間よりも幅が広い場合にのみ発生します。

対照的に、次のコード例では: 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  height: 50px;
  overflow: auto;
}

要素の高さは固定された 50px ですが、 contain-intrinsic-size は 100px の「推定コンテンツ高さ」を示します。 そのため要素は、実際のコンテンツで満たされたときに 垂直スクロールバーが必要になると想定し、 contain-intrinsic-size による 推定 100px の max-content 幅と、 垂直スクロールバーの幅（通常は約 16px）の両方を収めるため、 100px より少し広い max-content 幅 （通常は約 116px）になります。

ただし、要素がスクロールバーを必要とするという想定のもとで空間を確保していても、 実際のコンテンツがオーバーフローしない限り、 スクロールバーを実際に生成することはありません。 最終的に高さ 50px 未満のコンテンツを含む場合、 垂直スクロールバーはまったく生成されませんが、 要素の幅は引き続き 116px になります。

<meta name="responsive-embedded-sizing">
<div style="height: 500px"></div>

そして、埋め込む文書に次の CSS がある場合:

iframe {

}

iframe の高さは最初、既定の iframe 高さ（通常は 150px）になりますが、 iframe の文書が読み込まれると 500px に更新されます。

5.3.1. HTML iframe の詳細

HTML では、 iframe 要素だけが内部レイアウト内在サイズを持つことができ、 さらに、 iframe の 埋め込み文書が適切にオプトインしている場合に限られます。

HTML Document オブジェクトには、 レスポンシブ埋め込みサイズ指定フラグが関連付けられており、 初期状態では未設定です。 これは文書の初期解析中に、 次のいずれかが最初に発生したかに応じて、 true または false に設定されます:

  • <meta name=responsive-embedded-sizing> 要素に遭遇した場合、 true に設定されます。

  • body 要素が（明示的または暗黙的に）開かれた場合、 またはパーサーによって文書に挿入された場合、 false に設定されます。

true または false のいずれかに設定されると、 このフラグは Document の存続期間中、再び値が変更されることはありません。

注: 現在、HTML 文書の meta 要素が head 内に現れることが、 HTML において埋め込み文書がこの機能にオプトインする唯一の方法です。 これは、 iframe 内の SVG 文書はオプトインできないことを意味します。

注: HTML パーサーの特性により、 meta 要素は技術的には head 要素と body 要素の間に現れることができ、 head 内へ再親子付けされます。 この場所も <meta name=responsive-embedded-sizing> 要素にとって有効です。 なぜなら、 body はまだ開かれていないためです。 ほとんどの HTML 要素は、 body 開始タグが存在しない場合でも、 body 要素を暗黙的に開くことに注意してください。 また、文書にそのような要素がまったく存在しない場合、 空の要素が自動的に生成されて挿入されます。

内部レイアウト内在サイズは最初に、 埋め込み文書が DOMContentLoaded イベントを発火した後の最初のレイアウト結果によって設定され、 さらに load イベントが Window で発火したときにも設定されます。 その後の埋め込み文書のコンテンツ、スタイル、またはレイアウトの変更は、 内部レイアウト内在 サイズに自動的には影響しませんが、 requestResize() も参照してください。

埋め込み文書はさらに、ロックされた埋め込み ICB サイズを持つことができ、 初期値は null です。 文書のレスポンシブ埋め込みサイズ指定フラグが レイアウト実行時に true であり、 かつロックされた埋め込み ICB サイズが null の場合、 現在の初期包含ブロックのサイズを、ロックされた埋め込み ICB サイズとして記録します。 以降のレイアウトでは、 初期包含ブロックのサイズを通常どおり計算する代わりに、 ロックされた埋め込み ICB サイズを使用します。

注: この ICB の固定により、 レイアウトループが発生する可能性が低減されます （iframe 文書がその ICB よりわずかに大きくサイズ指定され、 それに合わせて親 iframe のサイズが変更され、 次のレイアウトで再び ICB よりわずかに大きくなり、 これが無限に続く、といった状況です）。

iframe にロックされた埋め込み ICB サイズを強制的に忘れさせる方法を 用意する必要があるでしょうか？ frame-sizing を一度オフにして再びオンにする方法でしょうか？

iframe の文書をナビゲートすると、 ロックされた埋め込み ICB サイズを忘れます。 新しい文書のレスポンシブ埋め込みサイズ指定フラグが未設定である限り、 内部レイアウト内在サイズを忘れることはありません。 フラグが（true または false に）設定されると、 内部レイアウト内在サイズは忘れられます。 フラグが true に設定された場合、 その後、両方が通常どおり新たに計算されます。

CSS Sizing 3 § 5.2 内在サイズへの寄与

5.5. Min-Content サイズへの寄与をゼロにする: min-intrinsic-sizing プロパティ

名前: min-intrinsic-sizing
値: legacy | zero-if-scroll || zero-if-extrinsic
初期値: legacy
適用対象: インライン ボックスを除くすべての要素
継承: しない
パーセント値: 該当なし
算出値: 指定どおり
正規順序: 文法に従う
アニメーション型: 離散

このプロパティの名前は本格的に Bikeshed で検討する必要があります。

このプロパティは、非置換ボックスのmin-content への寄与を、 特定の状況で「圧縮」するかどうかを定義します。 各値の意味は次のとおりです:

legacy
ボックスのmin-content への寄与は、 通常どおり処理されます。
zero-if-scroll
ボックスのmin-content への寄与は、 その軸でスクロール コンテナーである場合に「圧縮」されます。
zero-if-extrinsic
ボックスのmin-content への寄与は、 外在的な 優先サイズまたは最大サイズを持つ場合に 「圧縮」されます。

注: これは、ほとんどの置換要素の既定の動作です。

次の規則により、すべてのスクロール コンテナーは、 サイズへの寄与を親へ伝える際に、 実質的にそのコンテンツを無視するようになります （コンテンツに基づくサイズを明示的に要求した場合を除きます）: 
*, ::before, ::after { min-intrinsic-sizing: zero-if-scroll; }

これにより、スクロールコンテナーに、 表や改行不能な長いテキスト行などの大きな項目が含まれる場合でも、 その祖先のサイズを過度に拡大することを防ぎます。 一方、スクロールコンテナーではないボックスは、 その祖先のmin-content サイズに引き続き影響を与えることができます。

注: zero-if-scroll の動作を既定にした方が より適切でしたが、 Web 互換性のため、初期値にはできません。:(

「圧縮された」min-content への寄与は、 ボックスが空であると仮定して計算されます。 ただし、サイズ指定プロパティの明示的な min-content、max-content、および fit-content 値によって課される サイズ指定制約を考慮する場合を除きます。

5.6. 新しい列サイズ指定値: stretch、min-content、max-content、fit-content、および fit-content() 値

名前: column-width
新しい値: <box-size>
算出値: <length-percentage> 値を算出した、指定どおりの値
アニメーション型: 算出値の型による

column-width の値として使用された場合、 新しいキーワードは最適な列幅を指定します:

stretch
最適な列幅を、マルチカラムコンテナーのstretch-fit インラインサイズとして指定します。
min-content
最適な列幅を、マルチカラムコンテナーのコンテンツのmin-content インラインサイズとして指定します。
max-content
最適な列幅を、マルチカラムコンテナーのコンテンツのmax-content インラインサイズとして指定します。
fit-content
最適な列幅を min(max-content インラインサイズ, max(min-content インラインサイズ, stretch-fit インラインサイズ)) として指定します。
fit-content(<length-percentage>)
最適な列幅を min(max-content サイズ, max(min-content サイズ, <length-percentage>)) として指定します。

注: 列幅が列ごとに異なることはありません。 列幅がマルチカラムコンテナーのコンテンツから決定される場合 （上記のキーワードの場合）、 そのすべてのコンテンツが考慮され、 計算された幅がすべての列で共有されます。

6. 外在サイズの決定

CSS Sizing 3 § 4 外在サイズの 決定

6.1. Contain-fit サイズ指定: アスペクト比を維持しながら引き伸ばす

Contain-fit サイズ指定は基本的に stretch-fit サイズ指定を適用しますが、 ボックスの優先アスペクト比を維持するために、 一方の軸でボックスのサイズを縮小します。 これは、object-fit および background-size プロパティの contain キーワードに似ています。

まず、対象矩形を決定します:

  1. 初期対象矩形はボックスの包含ブロックのサイズであり、 不定なサイズは無限大であると仮定します。 両方の寸法が不定の場合、 初期対象矩形は、 ボックスがstretch-fit サイズ指定された場合の 外縁に一致するよう設定されます。
  2. 次に、ボックスが none 以外の max-width または max-height を持つ場合、 対象矩形は影響を受ける寸法において、 ボックスのマージンボックスの「最大サイズ」以下になるよう制限されます。 つまり、ボックスが max-width/height でサイズ指定された場合の マージンボックスのサイズです。 （通常の box-sizing 規則と整合して、 この「最大サイズ」はボックスの min-width/min-height の効果によって下限が設定されることに注意してください。）
  3. 最後に、対象矩形がボックスの優先アスペクト比に一致するために 必要な最小限だけ、一方の寸法を縮小します。

各寸法における contain-fit サイズは、 対象矩形へ stretch-fit した場合に得られるサイズです。

マージンの相殺に関して stretch-fit が最終的に行うことをそのまま適用する。

一方の寸法に最小サイズがあり、 アスペクト比を尊重すると対象矩形からオーバーフローする場合、 アスペクト比を尊重するのでしょうか、それとも画像を歪ませるのでしょうか？ 前者の場合、関連する最小値を適用する #2 と同様の手順が必要です。
