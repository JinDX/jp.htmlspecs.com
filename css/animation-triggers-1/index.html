概要

ユーザー操作から生じる DOM イベント、またはアニメーションタイムライン上の 範囲への進入／退出に基づいて、アニメーションの再生に影響を与える仕組みを 作成するための CSS プロパティと API を定義する。

CSS は、構造化された文書 （HTML や XML など）の画面や紙などへの 描画を記述する言語である。

1. はじめに

この仕様は、アニメーションの再生に 影響を与える仕組みを定義する。 これは、指定されたトリガーを呼び出す様々なユーザー操作に基づく。 アニメーションにトリガーを指定すると、そのアニメーションは トリガー付きアニメーションとなり、 トリガーが発生するまで再生開始が遅延される。 これらのトリガーは、特定の Event（[DOM] で定義） に結び付けることも、 ビュー進行タイムラインなどのタイムラインに基づくものにもできる。[SCROLL-ANIMATIONS-1]

このモジュールは、Web Animations API に基づく命令型 API と、 CSS Animations に基づく宣言型 API の 両方を提供する。[CSS-ANIMATIONS-2] [WEB-ANIMATIONS-1]

1.1. 他の仕様との関係

Web Animations [WEB-ANIMATIONS-1] は、 Web プラットフォーム上のアニメーションの抽象的な概念モデルを定義する。 そのモデルの要素にはアニメーションとタイムラインが含まれ、 関連するプログラミングインターフェイスも定義する。 この仕様は Web Animations モデルを拡張し、 トリガー付きアニメーションを定義するとともに、 トリガーを使ってそれらに再生制御の 機能を実行できるようにする。

この仕様は、これらの概念とやり取りするための プログラミングインターフェイスと、 これらの概念を CSS Animations に適用する CSS プロパティの両方を導入する。[CSS-ANIMATIONS-2] これらの CSS プロパティの動作が プログラミングインターフェイスを用いて記述されている場合でも、 スクリプトをサポートしないユーザーエージェントは、 この仕様に適合できる。 そのためには、基礎となるプログラミングインターフェイスが存在するかのように CSS 機能が動作するよう実装すればよい。

この仕様は、Scroll-Driven Animations モジュール [SCROLL-ANIMATIONS-1] が導入したタイムラインと範囲の概念を用いて、 進行に基づくタイムラインとアニメーションを規定する。

セレクターの照合を除く CSS の大半の操作と同様に、 この仕様の機能は、 平坦化された要素ツリー上で動作する。

1.2. 値の定義

この仕様は、 CSS プロパティ定義規則 （[CSS2]）に従い、 値定義構文 （[CSS-VALUES-3]）を使用する。 この仕様で定義されていない値型は、 CSS Values & Units [CSS-VALUES-3] で定義される。 他の CSS モジュールとの組み合わせによって、これらの値型の定義が拡張されることがある。

各プロパティの定義に列挙された固有の値に加えて、 この仕様で定義するすべてのプロパティは、 CSS 全域キーワードもプロパティ値として受け付ける。 読みやすさのため、明示的な繰り返しは省略している。

2. トリガー

トリガーは、一つの要素上のユーザー操作を、 別の（または同じ）要素への指定されたアクションの適用に結び付ける。

現在、二種類のトリガーが定義されている：

  • タイムライントリガーは、timeline-trigger プロパティで管理され、 特定のタイムライン範囲への進入または退出によってアクションを発火できる。 （通常はビュー進行タイムラインを使用するため、 例えば、要素が画面に入ったときにアニメーションを開始できる。）

  • イベントトリガーは、event-trigger プロパティで管理され、 要素のクリックや特定のキーの押下などの ユーザー操作イベントでアクションを発火できる。

トリガーは、特定の発火要素上で定義される。 すべてのトリガーにはトリガー名があり、 トリガーの具体的な種類が、活性化の方法とタイミングを決める。

トリガーが定義されると、その種類のトリガーインスタンスが、 trigger-scope プロパティで管理されるスコープ内に作成される。 指定された各発火要素に対し、トリガーアタッチメントが、 対応するインスタンス上に作成される。その名前 および trigger-scope は一致している。

トリガーアタッチメントの具体的な「種類」が、関連する インスタンスの「グループ化」を決める。つまり、イベントトリガーのアタッチメントは、 名前とスコープが同じなら、一つの インスタンスにまとめられる。同様に、タイムライントリガーは、 それとは別にグループ化される。 ただし、同じスコープで異なる種類のトリガー名を定義すると、 以前に定義されたトリガー名を上書きする。

トリガーは、任意の要素上で使用できる。 これにより、その要素上でトリガーインスタンスとの関連付けが作られる。 そのインスタンスは同じ名前を持つ。 （例えば、animation-trigger はトリガーインスタンスを、 要素上の特定のアニメーションに関連付ける。） トリガーを使用する要素は、 関連するトリガーの活性化または非活性化時に行うアクションを指定する。

注： トリガーとトリガーインスタンスの設計、および それらをトリガー付きアニメーションや <animation-action> に関連付ける方法は、 意図的にある程度汎用的なものとしている。 将来、トリガーを他の目的に使えるようにするためである。 ただし現時点では、トリガー付きアニメーションだけがこの機能を使う。

2.1. トリガーアクション

トリガーを要素上でトリガーとして使用する場合、 一つまたは二つのアクションを関連付けられる （例えば animation-trigger による）。 二つを指定した場合、最初はトリガーの進入アクションであり、 トリガーが活性化されたときに適用するアクションである。 二番目はトリガーの退出アクションであり、 トリガーが非活性化されたときに適用するアクションである。

2.2. トリガーの内部状態

トリガーインスタンス trigger は、内部の真偽値フラグ発火済みを持つ。 その初期値は false である。また、内部状態を持ち、 次の値を取り得る：

保留
初期 状態 。 トリガー の 発火済み フラグが false の間はこの状態になる。
活性
この値に切り替わると、 トリガー は指定された次のアクションを適用する： 進入アクション.
非活性
この値に切り替わると、 トリガー は指定された次のアクションを適用する： 退出アクション.

2.3. トリガー名のスコープ： trigger-scope プロパティ

トリガー名は既定では大域的であり、 他の要素は位置にかかわらず使用できる。 （ただし、これらはツリースコープ名なので、 シャドールートとの相互作用がある。） 複数の要素がトリガーを同じトリガー名で宣言すると、 それらは別々のアタッチメントとしてまとめられ、 同じトリガーインスタンスに属する。そのトリガー名と種類は同じである。

trigger-scope プロパティは、名前のスコープを 文書の部分ツリーに制限できる。 その外側の要素には選択されたトリガー名が見えなくなり、 内側の要素にはトリガー名のうち、 そのスコープ内で定義されたものだけが見える。

名前： trigger-scope
値： none | all | <dashed-ident>#
初期値： none
適用対象： すべての要素
継承： しない
百分率： 適用なし
算出値： 指定されたとおり
正規順序： 文法に従う
アニメーション型： アニメーション不可

このプロパティは、トリガー名のスコープを一致した要素の部分ツリーに制限する。 値は次のとおり：

none
変更しない対象は トリガー名 のスコープである。
all
次のすべての トリガー名 （この要素または子孫が定義し、子孫によって次を用いてスコープがまだ制限されていないもの）： trigger-scope）について、スコープ内となるのをこの要素の 平坦ツリー の子孫に限定する。 さらに、子孫による次の照合対象を限定する： トリガー名 の照合先は トリガー であって、このサブツリー内にあるものだけとする。

この値が影響するのは、同じツリースコープのトリガー名だけであり、 厳密に照合されるツリースコープ名であるかのように動作する。 （つまり、trigger-scope: all は、 trigger-scope: --foo, --bar, ... によって 関連するすべてのトリガー名を列挙した場合と同じように動作する。）

<dashed-ident>
一致する トリガー名 （この要素または子孫が定義し、子孫によって次を用いてスコープがまだ制限されていないもの）： trigger-scope）について、スコープ内となるのをこの要素の 平坦ツリー の子孫に限定する。 さらに、子孫によるこれらの照合対象を限定する： トリガー名 の照合先は トリガー であって、このサブツリー内にあるものだけとする。

<dashed-ident> は、厳密に照合されるツリースコープ名を表す。 すなわち、同じシャドーツリーのトリガー名だけに一致する。[CSS-SCOPING-1]

3. タイムライントリガー

タイムライントリガーはトリガーの一種であり、 あるタイムラインが そのトリガーの活性化範囲に入ると活性化し、 活性範囲から出ると非活性化する。 要素上で timeline-trigger 一括指定プロパティ、 またはその個別プロパティによって定義する。要素上で定義すると、 アタッチメントが作られ、トリガーインスタンスに結び付く。 そのインスタンスは指定された名前とスコープを持つ。

要素は、複数のタイムライントリガーを定義でき、 同じタイムライン（範囲が異なっていてもよい） または異なるタイムラインを使用できる。 timeline-trigger 個別プロパティの集合は、 協調リストプロパティグループを構成する。 timeline-trigger-name を協調リスト基底プロパティとし、 協調値リストの各項目が、 一つのタイムライントリガーのプロパティを定義する。

3.1. タイムライントリガーの範囲

タイムライントリガーのアタッチメントには、一つ以上のタイムラインを関連付けられる。 すべての、このアタッチメントに関連する 活性化範囲に入ると、 関連するトリガーインスタンスを活性化し、 その状態を活性にする。 いずれか一つの、このアタッチメントに関連する 活性範囲から出ると、 関連するトリガーインスタンスを非活性化し、その状態を 非活性にする。 したがって、実質的には、トリガーに関連する全タイムラインの状態の論理和となる。 例えば、要素が、 垂直かつ水平のスクロール領域の交差領域に入る場合である。

注： 既定では、活性範囲は活性化範囲と同じである。 手動で指定した場合でも、 活性範囲は常に上位集合であり、活性化範囲を包含する。 例えば、この二つの範囲により、 animation-trigger は、要素が 画面中央の近くまでスクロールされたときにアニメーションを開始できる （ビュー進行タイムラインを使い、比較的小さい区間を活性化範囲とする）。 一方、要素が完全に画面外になるまで停止しないようにできる （cover を活性範囲として使う）。

3.2. トリガーの命名： timeline-trigger-name プロパティ

名前： timeline-trigger-name
値： none | <dashed-ident>#
初期値： none
適用対象： すべての要素
継承： しない
百分率： 適用なし
算出値： 指定されたとおり
正規順序： 文法に従う
アニメーション型： アニメーション不可

none を指定すると、 要素はタイムライントリガーを定義しない。

同じ <dashed-ident> がリスト内に複数回現れた場合、 最後のものだけがタイムライントリガーを定義し、 それ以前のものは効果を持たない。

3.3. タイムラインの関連付け： timeline-trigger-source プロパティ

名前： timeline-trigger-source
値： [ none | auto | [ <dashed-ident> | <scroll()> | <view()> ]+ ]#
初期値： auto
適用対象： すべての要素
継承： しない
百分率： 適用なし
算出値： 指定されたとおり
正規順序： 文法に従う
アニメーション型： アニメーション不可

timeline-trigger-source プロパティは、 タイムライントリガーに関連するタイムラインを指定する。 値の意味は animation-timeline と同じである。

注： none の場合、 トリガーはタイムラインに関連付けられない。 タイムライントリガーにタイムラインがないと、<animation-action> は実行できない。 状態を監視したり変更したりできないためである。

3.4. 活性化範囲： timeline-trigger-activation-range プロパティ

名前： timeline-trigger-activation-range
値： [ <'timeline-trigger-activation-range-start'> <'timeline-trigger-activation-range-end'>? ]#
初期値： 個々のプロパティを参照
適用対象： 個々のプロパティを参照
継承： 個々のプロパティを参照
百分率： 個々のプロパティを参照
算出値： 個々のプロパティを参照
アニメーション型： 個々のプロパティを参照
正規順序： 文法に従う

timeline-trigger-activation-range プロパティは一括指定プロパティであり、 timeline-trigger-activation-range-start と timeline-trigger-activation-range-end を、 一つの宣言で同時に設定する。 構文は animation-range プロパティと同じである。

timeline-trigger-activation-range の動作は§ 3.1 タイムライントリガーの範囲で定義する。

名前： timeline-trigger-activation-range-start, timeline-trigger-activation-range-end
値： [ normal | <length-percentage> | <timeline-range-name> <length-percentage>? ]#
初期値： normal
適用対象： すべての要素
継承： しない
百分率： 指定された 名前付きタイムライン範囲 があればその範囲に対する相対値、それ以外はタイムライン全体に対する相対値
算出値： 各項目がキーワード normal またはタイムライン範囲と進行の百分率であるリスト
正規順序： 文法に従う
アニメーション型： アニメーション不可

timeline-trigger-activation-range-start と timeline-trigger-activation-range-end は、 タイムライントリガーに関連する活性化範囲を指定する。 値の意味は animation-range-start および animation-range-end と同じである。

4. イベントトリガー

イベントトリガーはトリガーの一種であり、 要素で特定の Event が発火すると活性化する。 要素上で event-trigger 一括指定プロパティ、 またはその個別プロパティによって定義する。

イベントトリガーは、状態なし、または状態ありとして定義できる：

  • 状態なしの場合、単一の進入イベントの集合があり、 それらがトリガーを活性化する。

  • 状態ありの場合、二つのイベント集合を持つ。進入イベントの集合と、 もう一つの退出イベントの集合である。

イベントトリガーは、関連するいずれかの Event がページ上で発火すると活性化する。 その target は、トリガーを定義した要素である。 状態ありの場合、 二値のトリガー状態が関連付けられ、 初期値は "inactive" である： "inactive" の間は、定義した要素が進入イベントを受け取ったときだけ活性化し、 関連する進入アクションを実行し、 トリガー状態を "active" に切り替える。 "active" の間は、退出イベントを受け取ったときだけ非活性化し、 関連する退出アクションを実行し、 トリガー状態を "inactive" に戻す。

状態なしのイベントトリガーは、トリガーインスタンスにちょうど一つのアクションを指定しなければならない。 状態ありの場合は、一つまたは二つを指定できる： 最初は進入アクション、 二番目があれば、それは退出アクションとなる。 二番目を指定しなかった場合、 退出アクションは何もしない。

注： 状態ありと状態なしのイベントトリガーは、 一つのアクションしか指定しない場合でも異なる動作をする。 単一アクションの状態ありイベントトリガーは、実質的に「オフ」になり、 退出イベントを受け取るまで、 最初より後の進入イベントをすべて無視する。 状態なしの場合は、各進入イベントで繰り返し発火する。

要素は、複数のイベントトリガーを定義でき、 同じ、または異なる Event を使用できる。 event-trigger 個別プロパティの集合は、 協調リストプロパティグループを構成する。 event-trigger-name を協調リスト基底プロパティとし、 協調値リストの各項目が、 一つのイベントトリガーのプロパティを定義する。

この文章を引用した提案では、 要素がイベントのターゲットであるかだけを考慮すると規定していた。 バブリングやキャプチャーも認めたいと思われる。 選択的に有効化／無効化できるようにしてもよいだろう。

5. トリガー付きアニメーション

CSS アニメーションは既定では、要素に 適切な animation 値を設定すると直ちに自動実行される。 animation-trigger プロパティは、アニメーションの開始を、 適切なトリガーが発生するまで遅延できるようにする。 さらに、トリガーによる一時停止、再開始、リセットも可能になる （これをトリガー付きアニメーションとする）。

スタイルシート
一つの CSS スタイルシート.
レンダラー

オーサリングツールは、CSS の汎用文法と このモジュールの各機能の個別の文法に従って 構文的に正しいスタイルシートを作成し、 このモジュールに記載されたスタイルシートの 他のすべての適合性要件を満たす場合、この仕様に適合する。

部分的な実装

作者が前方互換の解析規則を利用して フォールバック値を割り当てられるように、CSS レンダラーは必ず、 利用可能なサポートを持たない構文を無効として扱い、適宜 無視しなければならない。対象には at 規則、プロパティ、プロパティ値、キーワード、 および他の構文上の構成物が含まれる。 特に、ユーザーエージェントはしてはならない：一つの複数値プロパティ宣言で、 非対応の成分値だけを選択的に無視し、対応する値を採用すること。 いずれかの値が無効とみなされた場合 （非対応の値は必ず無効とみなす）、CSS は、 宣言全体を無視することを要求する。

仕様が勧告候補の段階に達すると、 非実験的な実装が可能になる。実装者は、 仕様に従って正しく実装したことを示せる CR レベルの機能について、 接頭辞なしの実装を公開することが望ましい。

実装間の CSS の相互運用性を 確立し維持するため、CSS 作業グループは非実験的な CSS レンダラーに対し、CSS 機能の接頭辞なし実装を公開する前に、 W3C へ実装報告を提出するよう求める。 必要な場合は、その報告に使ったテストケースも提出する。 W3C に提出されたテストケースは、CSS 作業グループによるレビューおよび修正の対象となる。

テストケースと実装報告の提出についての詳細は、 CSS 作業グループのウェブサイト、 https://www.w3.org/Style/CSS/Test/ で確認できる。 質問は、 public-css-testsuite@w3.org メーリングリストに送ること。
