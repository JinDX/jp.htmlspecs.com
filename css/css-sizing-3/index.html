概要

このモジュールは、コンテンツに基づく「内在」サイズ およびコンテキストに基づく「外在」サイズを表すキーワードによって CSS のサイズ指定プロパティを拡張し、CSS でコンテンツに適合するボックスや 特定のレイアウトコンテキストに適合するボックスをより簡単に記述できるようにします。

CSS は、構造化文書 （HTML や XML など）の画面、紙面などへのレンダリングを記述するための言語です。

1. はじめに

この節は規範的ではありません。

CSS レイアウトには、さまざまなレイアウト計算で使用される自動サイズ指定に関する複数の異なる概念があります。 この節では、より正確な用語をいくつか定義し、 この仕様のレイアウト動作と他のモジュールで使用される計算との関連付けを容易にするとともに、 width および height プロパティ用の新しいキーワードをいくつか定義して、 これらのサイズ計算から得られる寸法を要素に割り当てられるようにします。

1.1. モジュール間の相互作用

このモジュールは、[CSS2] の第10章および [CSS3COL] で定義されている width、height、min-width、min-height、max-width、max-height、および column-width の機能を拡張します。

このモジュールにおける box-sizing プロパティの定義は、[CSS-UI-3] の定義に優先します。

1.2. 値の定義

この仕様は、[CSS2] の CSS プロパティ定義規約に従い、 [CSS-VALUES-3] の 値定義構文を使用します。 この仕様で定義されていない値型は CSS Values & Units [CSS-VALUES-3] で定義されています。 他の CSS モジュールとの組み合わせにより、これらの値型の定義が拡張される場合があります。

各定義に列挙されているプロパティ固有の値に加えて、 この仕様で定義されるすべてのプロパティは、 プロパティ値として CSS 全域キーワードも受け入れます。 可読性のため、それらは明示的に繰り返していません。

2. 用語

座標軸および寸法に関する主要な用語の一部は、 CSS Writing Modes 3 § 6 抽象ボックス用語で定義されています。

サイズ
1次元または2次元の測定値: ブロックサイズおよび／または インラインサイズ。 あるいは 幅および／または 高さ。
内側サイズ
ボックスの コンテンツボックスの サイズ。
外側サイズ
ボックスの マージンボックスの サイズ。
確定サイズ
レイアウトを実行せずに決定できるサイズ。 すなわち、<length>、 テキストの測定値（行折り返しを考慮しない）、 初期包含ブロックのサイズ、 または <percentage> もしくはその他の式 （たとえば非置換ブロックの「stretch-fit」サイズ指定 [CSS2]） であり、確定サイズのみに対して解決されるもの。

さらに、絶対配置要素の包含ブロックのサイズは、その要素に関して常に 確定です。

不確定サイズ
確定ではないサイズ。 不確定な利用可能空間は、本質的に 無限です。

注: 内在サイズ指定キーワード（max-content など）は不確定です。 サイズ包含や子が存在しないことなどにより、 子をレイアウトせずに決定できる場合でも同様です。

利用可能 空間
ボックスがレイアウトされる空間を表すサイズであり、 そのボックスが参加する整形コンテキストの規則によって決定されます。 ボックスに利用可能な空間は通常、 その包含ブロックの測定値（それが確定である場合）、 または無限サイズ（不確定である場合）のいずれかです。 利用可能空間は、代わりに min-content 制約または max-content 制約 のいずれかであることもでき、その空間内に配置されるボックスにその制約の下でのレイアウトを強制します。

stretch fit
指定されたサイズへのstretch fitは、 そのサイズから、指定された次元におけるボックスの算出済みマージン （相殺せず、auto をゼロとして扱う）、境界、およびパディングを差し引いたものです （外側サイズが完全に適合するようにします）。 また、ゼロを下限とします （内側サイズが負にならないようにするためです）。

注: これは CSS2.1§10.3.3 において、 通常フロー内の非置換ブロックの auto 幅を計算するために使用される式です。

フォールバックサイズ
一部のサイズ指定アルゴリズムは、無限サイズでは適切に機能しません。 そのような場合、代わりにフォールバックサイズが 使用されます。 特に指定がない限り、 これは初期包含ブロックのサイズです。

2.1. 自動ボックスサイズ

CSS には、自動的に決定されるサイズが4種類あります （コンテキストに応じて auto サイズ指定規則から得られるサイズ）:

stretch-fit サイズ
stretch-fit インライン サイズ
stretch-fit ブロック サイズ
指定された軸において、ボックスの外側サイズが 利用可能空間を満たす場合に、 ボックスが取るサイズ。 言い換えると、利用可能空間が 確定である場合、その空間への stretch fitです。 利用可能空間が不確定である場合は未定義です。

注: インライン 軸では、これは CSS2.1§10.3.5 において「利用可能幅」と呼ばれ、 CSS2.1§10.3.3 の規則によって計算されます。

注: このサイズを含む計算では、 利用可能空間が 不確定になり得る場合、 その場合のフォールバック動作を指定する必要があります。

max-content サイズ
無限の利用可能空間が与えられた場合に、指定された軸でボックスが取る「理想的な」 サイズ。 通常これは、コンテンツを収めたままその軸でボックスが取ることのできる最小の サイズであり、 すなわち、オーバーフローを回避しつつ未使用空間を最小化します。
max-content インラインサイズ

インライン軸におけるボックスの「理想的な」サイズ。 通常は、ボックス内のソフト折り返し機会を一切使用しない場合に、 コンテンツを収めることができる最も狭いインラインサイズです。 （§ 5 内在サイズの決定を参照。）

注: これは CSS2.1§10.3.5 では「優先幅」と呼ばれ、 CSS2.1§17.5.2.2 では「最大セル幅」と呼ばれます。

max-content ブロックサイズ

ブロック軸におけるボックスの「理想的な」サイズ。 通常は、レイアウト後のコンテンツのブロック サイズです。

理想的なmax-content サイズがmin-content サイズより小さくなる場合 （たとえば負のマージンを使用したことによる場合）、 実効的なmax-content サイズはmin-content サイズを下限とします。

min-content サイズ
名目的には、より大きなサイズを選択することで回避できる オーバーフローを生じさせない範囲で、ボックスが取ることのできる最小の サイズです。 形式的には、min-content 制約の下でサイズ指定されたときのボックスのサイズです。 § 5 内在サイズの決定を参照してください。
min-content インラインサイズ

インライン軸における min-content サイズ。 通常、ボックス内のすべてのソフト折り返し機会を使用した場合に、 コンテンツを収められるインライン サイズです。

注: これは CSS2.1§10.3.5 では「優先最小幅」、 CSS2.1§17.5.2.2 では「最小コンテンツ幅」と呼ばれます。

min-content ブロックサイズ

ブロック軸における min-content サイズ。 ブロックコンテナー、テーブル、およびインライン ボックスでは、 これはmax-content ブロックサイズと等価です。

fit-content サイズ
fit-content インライン サイズ
fit-content ブロック サイズ
指定された軸の利用可能空間が 確定である場合、 次と等しくなります: clamp(min-content サイズ, stretch-fit サイズ, max-content サイズ) （すなわち max(min-content サイズ, min(max-content サイズ, stretch-fit サイズ))）。 min-content 制約の下でサイズ指定する場合は、 min-content サイズと等しくなります。 それ以外の場合は、その軸におけるmax-content サイズと等しくなります。

注: これは CSS2.1§10.3.5 および CSS Multi-column Layout § 3.4 では「shrink-to-fit」幅と呼ばれます。

内在サイズ
max-content サイズまたはmin-content サイズ、 すなわち、主としてコンテンツのサイズから生じるサイズです。 （この用語の一部の用法では、これら2つのサイズのいずれかから主として導出されるサイズも指す場合があります。）

置換要素は、その内在サイズを、 自然寸法から導出することがよくあります。

次の例では、内側の <div> の幅に fit-content サイズ指定を適用し、 さまざまなサイズの包含ブロック内に配置します:

  • 最も狭い包含ブロック（2ch）では、 ボックスはmin-content サイズを取ります。つまり、可能な限り狭く折り返された すべてのコンテンツを完全に収めるために、包含ブロックからオーバーフローします。

  • 中央の包含ブロック（9ch）では、 ボックスはstretch-fit サイズを取ります。つまり、コンテンツを内部に収まるよう 折り返しながら、包含ブロックを正確に満たします。

  • 最も広い包含ブロック（16ch）では、 ボックスはmax-content サイズを取ります。つまり、包含ブロックより小さいものの、 折り返されていないコンテンツを正確に囲みます。

<!DOCTYPE html>
<style>div > div { width: fit-content; }</style>
<div style="width: 2ch;">
  <div>abc def ehg</div>
</div>
<div style="width: 9ch;">
  <div>abc def ehg</div>
</div>
<div style="width: 16ch;">
  <div>abc def ehg</div>
</div>

ここで width の代わりに min-width または max-width プロパティを使用すると、 これらと同じサイズがそれぞれ最小幅または最大幅として適用され、 優先幅を制約して 使用幅を決定します。 § 3 ボックスサイズの指定および § 3.2 サイズ指定 値: <length-percentage>、auto | none、stretch、min-content、max-content、および fit-content 値を参照してください。

2.2. 内在サイズ寄与

max-content 寄与
ボックスがその包含ブロックのmax-content サイズに寄与するサイズ。
min-content 寄与
ボックスがその包含ブロックのmin-content サイズに寄与するサイズ。
内在サイズ 寄与
max-content 寄与、min-content 寄与、 または同様に計算されるコンテンツベースのサイズ寄与。

内在サイズ寄与は、ボックスの外側サイズに基づきます。 この目的では auto マージンはゼロとして扱われます。

理想的なmax-content 寄与がmin-content 寄与より小さくなる場合 （たとえば負のマージンを使用したことによる場合）、 実効的なmax-content 寄与は min-content 寄与を下限とします。

2.3. 内在サイズ制約

max-content 制約
ボックスの包含ブロックによって課されるサイズ指定制約であり、 ボックスにmax-content 寄与を生成させます。
min-content 制約
ボックスの包含ブロックによって課されるサイズ指定制約であり、 ボックスにmin-content 寄与を生成させます。
優先アスペクト 比
ボックスに固有の幅:高さの比率であり、 さまざまなサイズ指定アルゴリズムに対し、 他のサイズ指定入力を尊重しながら可能な限りそのアスペクト比と一致するサイズを生成するよう バイアスをかけます。 特に指定がない限り、 ボックスの優先アスペクト比は、存在する場合にはその 自然アスペクト比であり、 そのコンテンツボックスに適用されます。 ほとんどのボックスには優先アスペクト比がありません。

3. ボックスサイズの指定

3.1. サイズ指定プロパティ

この節では、適用されるボックスの優先、最小、および最大サイズを指定する サイズ指定プロパティを定義します。 取り得る値は次の節、 § 3.2 サイズ指定値: <length-percentage>、auto | none、stretch、min-content、 max-content、および fit-content 値で定義されます。

フロー相対バリアント（inline-size、block-size など）は、 要素自身の書字モードを使用して対応付けられ、 物理対応物（width、height など）とは、 [CSS-LOGICAL-1] で定義されているように相互作用します。 CSS Writing Modes 3 § 6 抽象ボックス用語も参照してください。

CSS では、最小サイズと最大サイズの両方が 使用サイズを制約しますが、 最小サイズ制約が常に最も強い制約です。 さらに、内側サイズは常に ゼロを下限とします。

3.1.1. 優先サイズプロパティ: width、height、inline-size、およびblock-size プロパティ

名前: width, height, inline-size, block-size
値: auto | <box-size>
初期値: auto
適用対象: 非置換インラインを除くすべての要素
継承: しない
パーセント値: 包含ブロックの幅／高さに対する相対値
算出値: 指定どおり。ただし <length-percentage> 値は算出される
正規順序: 文法に従う
アニメーション型: 算出値の型による。fit-content() 内へ再帰する
論理プロパティ グループ: size

  width:        100px;

  border-left:  10px solid;

  width:        100px;
  padding-left: 60px;
  border-left:  60px solid;
  /* padding + border = 120px */
}

4.2. Stretch-fit サイズ指定: 包含ブロックを満たす

Stretch-fit サイズ指定は、 min-height/min-width/max-height/max-width による制約を尊重しつつ、 ボックスの主ボックスの外側サイズが 包含ブロックを可能な限り満たすために必要な長さに、 ボックスの使用サイズを設定しようとします。

パーセントサイズが確定値に解決できる軸で使用される場合

auto マージンをゼロとして扱い、 マージンボックスが包含ブロックを正確に満たすようサイズ指定します。 （これにより内側 サイズが負になる場合は、 代わりにマージンボックスを、 内側サイズがゼロになるようサイズ指定します。）

フロー内のブロックレベルボックスで、 独立整形コンテキストを形成するものについては、 包含ブロックのインラインサイズの代わりに、 行ボックスに利用可能な空間 （すなわち浮動体を除く）を使用します。

フロー内のブロックレベルボックスについて、 ブロック 軸のサイズを解決する際: パーセント値が基準とする祖先要素に ブロック始端の境界またはパディングがなく、 かつ独立整形コンテキストでない場合、 このサイズを計算する目的では、要素のブロック始端マージンをゼロとして扱います。 ブロック終端 マージンについても同様に扱います。

注: これはマージンが親のマージンと 相殺される効果を模擬します。 実際にマージンを抑制するわけではないため、 何らかの理由で要素が実際には親とマージン相殺できない場合、 stretch-fit サイズは、親に完全に収まるには実際には大きすぎる可能性があります。

それ以外

優先サイズプロパティでは、 auto として動作します。 最小サイズ プロパティでは、 0 として動作します。 最大サイズ プロパティでは、 none として動作します。

.inner { height: stretch; margin: 10px; }

（上側のマージンは実際に相殺されますが、 下側のマージンは相殺されません。 なぜなら、ボックスの下側マージンは、auto ではない高さを持つ親の 下側マージンとは隣接していないためです。 CSS 2 § 8.3.1 マージンの相殺を参照してください。 幸い、オーバーフローする下側マージンには視覚的な効果がありません。）

5.1. 内在サイズ

各軸におけるボックスのmin-content サイズは、 その軸で auto 優先サイズが与えられ （かつその軸に最小または最大サイズがなく）、 その包含ブロックがその軸でゼロサイズである浮動体であった場合に取るサイズです。 （言い換えると、「shrink-to-fit」でサイズ指定された場合に取る最小サイズです。）

各軸におけるボックスのmax-content サイズは、 その軸で auto 優先サイズが与えられ （かつその軸に最小または最大サイズがなく）、 その包含ブロックがその軸で無限サイズである浮動体であった場合に取るサイズです。 （言い換えると、「shrink-to-fit」でサイズ指定された場合に取る最大サイズです。）

min-content サイズとmax-content サイズをまとめて 内在サイズと呼びます。

注: ボックスに優先アスペクト比がある場合、 反対側の次元のサイズ制約が転送され、 検討対象の次元におけるauto サイズに影響する場合があります。 CSS2§10 を参照してください。

この仕様は、浮動体のサイズを決定する方法を定義しません。 [CSS2] を参照してください。 ただし、置換要素で自然サイズを持たないものの 内在サイズは、 以下で定義します:

非退化の優先アスペクト比を持つ場合:
min-content サイズには ゼロを使用します。

max-content サイズには:

  • 利用可能空間が インライン軸で確定している場合、 インラインサイズにはそのサイズへのstretch fitを使用し、 アスペクト比を使用してブロックサイズを計算します。

  • それ以外で、 ボックスの min-width または min-height の算出値として <length> がある場合、 そのサイズを使用し、アスペクト比を使用してもう一方の次元を計算します。 両方の次元に <length> の最小値がある場合、 全体としてより大きいサイズになる方を選択します。

5.2.1. パーセント指定されたボックスの内在寄与

パーセントでサイズ指定されたボックスの包含 ブロックのサイズが、 そのボックス自身の内在サイズ寄与に依存し、 循環依存が生じる場合があります。 そのようなボックスの内在サイズ寄与を計算するとき （コンテンツベースの自動最小サイズに関する計算を含む）、 内在サイズ寄与と同じ軸のサイズに対して解決される パーセント値（循環パーセントサイズ）は、 特別に解決されます:

  1. ボックスが非置換の場合、 最大サイズ プロパティまたは優先サイズプロパティ （width/max-width/height/max-height）のうち、 パーセント値を含む式 （10% や calc(10px + 0%) など）として指定され、 循環しているものの値全体は、 ボックスの内在サイズ寄与を計算する目的に限り、 そのプロパティの初期値として扱われます。 たとえば、width: calc(20px + 50%) を持つボックスでは、 その max-content 寄与は、width が auto であるかのように計算されます。 （ただし、ボックス自体を実際にサイズ指定する際には、 パーセント値は通常どおり使用されます。以下を参照してください。）
  2. 同様に、ボックスが置換である場合、 パーセント値を含む式として指定され、 循環している 最大サイズ プロパティまたは優先サイズプロパティの値全体は、 ボックスのmax-content 寄与を計算する目的に限り、 そのプロパティの初期値として扱われます。
  3. ボックスが置換である場合、 最大サイズ プロパティまたは優先サイズプロパティ （width/max-width/height/max-height）の値にある 循環 パーセント値は、 対応する軸のmin-content 寄与を計算するとき、 ゼロに対して解決されます。 （これが適用される HTML 要素の一覧については、 § 5.2.2 圧縮可能な置換要素を参照してください。） ボックスに優先アスペクト比もある場合、 このmin-content 寄与は、 反対側の軸の任意の<length-percentage> 最小サイズを 優先アスペクト比を通じて転送した値を下限とします。 このとき、そのようなパーセント値はゼロに対して解決します。

    転送する前に、転送されるパーセント値をゼロではなく包含ブロックに対して解決するべきでしょうか？ 議論を参照してください。

    UA はさらに、UI 上の考慮事項に基づいて min-content 寄与に下限を設定してもよいです。 たとえば、特定の UI 要素が表示されたままになることを保証する場合 （例: select のドロップダウン矢印）です。

    注: min-content 寄与は、常にそうであるように、 自身の軸の最小 サイズも下限とします。

    この規則は、 コンテンツベースの自動最小サイズ またはそれに対応するサイズ寄与を計算する場合にも適用され、 確定した「指定サイズ提案」を生成します。

  • 循環依存が、包含ブロック上の最小サイズ以外の ブロック軸サイズ （すなわち、多くのレイアウトモードではblock-size または max-block-size、 フレックス レイアウトでは flex-basis）によって導入され、 そのサイズがコンテンツのサイズに依存することになる場合、 ボックスのパーセント値は解決されず、代わりにauto として動作します。

  • それ以外の場合、パーセント値は包含ブロックのサイズに対して解決されます。 （包含ブロックのサイズは、その結果として得られるボックスのサイズに基づいて再解決されません。 したがって、コンテンツは包含ブロックからオーバーフローまたはアンダーフローする場合があります。）

注: これらの規則は、 CSS2§10.2、 CSS2§8.3、 および CSS2§8.4 において 以前は未定義だったこの循環ケースの動作を指定します。 また、CSS2§10.5 の動作は、 CSS2 では説明されていないレイアウトモード （フレックスレイアウトなど）については、 それぞれの仕様によって置き換えられていることにも注意してください。

たとえば、次のマークアップでは: 
<article style="width: min-content">
  <aside style="width: 50%;">
  LOOOOOOOOOOOOOOOOOOOONG
  </aside>
</article>

外側の <article> の幅を計算するとき、 内側の <aside> は width: auto として動作するため、 <article> は長い単語の幅に自身を設定します。 ただし、<article> の幅は「実際の」レイアウトに依存しなかったため、 <aside> を解決する目的では確定として扱われ、 その幅は <article> の半分に解決されます。

この例では、 
<article style="height:auto">
  <aside style="height: 50%;">
    <div class=block style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

ブロックレベル要素上のパーセントブロックサイズ （この場合はheight）は、 コンテンツによってサイズ指定される包含ブロック内では解決しないと定義されているため、 <aside> 上のパーセント高さは無視されます。 すなわち、auto が指定された場合とまったく同じように動作します。

min-height が内在的な場合でも、確定したheight に対して パーセント値を引き続き解決できるようにするかは未解決の問題です。 （CSS2 には「コンテンツに依存する高さ」について一般的な記述があります。 これは技術的にはそのケースに該当しますが、 CSS2 には min-height 用の コンテンツ依存キーワードがありませんでした。 これは新しいため、異なる動作にすることも可能だと考えています。）

次の例は、サイズがコンテンツに依存する包含ブロックに対して ブロック軸のパーセント値がどのように解決されるかを示します。

<article style="height:100px; min-height: min-content;">
  <aside style="height: 50%;">
    <div style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

<article> の初期高さは、指定どおり 100px です。 そのため、<aside> がパーセント値を解決すると、 高さは 50px になります。 ただし、height の代わりに min-height を代入して、 min-height を計算する必要があります。 これにより <aside> 上のパーセント値がauto として動作するため、 <aside> は最終的に高さ 150px になります。 したがって、コンテンツの合計高さは 180px になります。 これは指定された 100px の高さより大きいため、 <article> は高さ 180px に調整されます。

次に、パーセント値は元々（100px の）高さに対して解決可能だったため、 今度は 180px の高さに対して解決され、 <aside> は最終的に高さ 90px になります。 

<article style="height:auto; min-height: min-content;">
  <aside style="height: 50%;">
    <div class=block style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

この場合、包含ブロックの高さが auto （したがってコンテンツのサイズに依存する）ため、 <aside> 上のパーセント値は通常は解決されません。 代わりにauto として 動作し、 <aside> の高さは 150px、 <article> の初期高さは 180px になります。 min-height はこれを変更しません。 height: min-content; は height: auto; と同様に動作し、 同じサイズになります。 

<article style="height:100px; min-height: min-content;">
  <aside style="height: 200%;">
    <div style="height: 150px;"></div>
  </aside>
  <section style="height: 30px;"></section>
</article>

これは最初のコードブロックの変形であり、 同様の過程をたどります。 <aside> は最初、高さ 200px （包含ブロックの 100px の高さの 200%）に算出されようとします。 min-height の影響を計算すると、 パーセント値はauto として 動作し、 高さ 150px になります。 そして、包含ブロックの合計min-content 高さは 180px になります。 これは 100px より大きいため、 <article> は 180px にクランプされ、 パーセント値はこの新しい高さに対して解決され、 <aside> は最終的に高さ 360px となって <article> からオーバーフローします。

5.2.2. 圧縮可能な置換要素

HTML§14.4 [HTML] に列挙されている 置換要素に加えて、 次の HTML 要素も、上記のパーセント指定された置換要素の 規則の目的では置換 要素とみなされ、 width/height または max-width/max-height が 循環パーセントサイズで表される場合、そのmin-content 寄与を 圧縮できます:

  • input のうち、「button-like」ではない任意の type。 これは UA によって異なる場合があります。

    特定の UA において、ある type が button 要素と同様に表示され、 要素のレイアウトを決定する実際のコンテンツを含められる場合、 その type は「button-like」です。 ほとんどの UA では、"button"、"reset"、"submit"、"color" の各 type が button-like です。 一部の UA では "file" type も部分的に button-like であり、 テキスト入力（縮小可能）とボタン（button-like であり縮小不能）の組み合わせとして表示されます。

  • select、 textarea、 progress、 meter、 marquee。

これを max-width/height に適用することの Web 互換性および実装進捗を Issue 6348 で追跡しています。[Issue #6348]

自動レイアウトをサポートするため、 CSS はコンテンツに適合するようボックスをサイズ指定します。 これを、ボックスのサイズをスクリプトに返すことができる各種の [DOM] および [CSSOM] API と組み合わせることで、 コンテンツに関する情報が露出する可能性があります。 ただし、この情報は、ボックスのサイズを介して間接的に取得するよりも、 コンテンツについて DOM を調べることで、より直接かつ容易に取得できます。 コンテンツを調べることができないコンテナー （クロスオリジンの iframe など）も、外側のページにサイズ情報を公開しません。 ただし、画像などの置換要素が 自然サイズおよび／またはアスペクト比を公開する範囲は除きます。

セキュリティに関する考慮事項

この仕様について、新たなセキュリティ上の考慮事項は報告されていません。

適合性

文書の表記規則

適合性要件は、 記述的な表明と RFC 2119 の用語を組み合わせて表現されます。この文書の規範的な部分にあるキーワード “MUST”、 “MUST NOT”、 “REQUIRED”、 “SHALL”、 “SHALL NOT”、 “SHOULD”、 “SHOULD NOT”、 “RECOMMENDED”、 “MAY”、および “OPTIONAL” は、RFC 2119 に記載されているとおりに解釈するものとします。 ただし、可読性のため、この仕様ではこれらの語はすべて大文字では 表記されません。

明示的に非規範的と示された節、例、および注を除き、この仕様のすべてのテキストは規範的です。 [RFC2119]

テスト

この仕様の内容に関連するテストは、 このような「テスト」ブロックに記載される場合があります。 このようなブロックはいずれも非規範的です。

    適合性クラス

    この仕様への適合性は、 3つの適合性クラスについて定義されます:

    スタイルシート
    CSS スタイルシート。
    レンダラー
    スタイルシートの意味を解釈し、 それを使用する文書をレンダリングする UA。
    オーサリングツール
    スタイルシートを書き出す UA。

    このモジュールで定義されている構文を使用するすべての記述が、 一般的な CSS 文法およびこのモジュールで定義される各機能の個別の文法に従って有効である場合、 スタイルシートはこの仕様に適合します。

    レンダラーは、適切な仕様で定義されるとおりにスタイルシートを解釈することに加えて、 この仕様で定義されるすべての機能を正しく構文解析し、 それに応じて文書をレンダリングすることでサポートする場合、 この仕様に適合します。ただし、デバイスの制約により UA が文書を正しくレンダリングできないことによって、 UA が不適合になることはありません。（たとえば、UA は モノクロモニター上で色をレンダリングする必要はありません。）

    オーサリングツールは、 一般的な CSS 文法およびこのモジュール内の各機能の個別の文法に従って構文的に正しい スタイルシートを書き出し、 このモジュールで説明されるスタイルシートのその他すべての適合性要件を満たす場合、 この仕様に適合します。

    部分的な実装

    作成者が前方互換な構文解析規則を利用して フォールバック値を割り当てられるようにするため、CSS レンダラーは、 使用可能なレベルのサポートを持たないすべての at-rule、プロパティ、プロパティ値、キーワード、 およびその他の構文構造を無効として扱い（かつ必要に応じて 無視）なければなりません。特に、ユーザーエージェントは、 1つの複数値プロパティ宣言内で、サポートされていないコンポーネント値だけを選択的に 無視し、サポートされている値を有効にしてはなりません。 いずれかの値が無効とみなされる場合 （サポートされていない値は無効とみなされなければならないため）、 CSS では宣言全体を無視する必要があります。

    不安定な機能および独自機能の実装

    将来の安定した CSS 機能との衝突を避けるため、 CSSWG は、CSS の不安定な機能および独自拡張の実装について、 ベストプラクティスに従うことを推奨します。

    非実験的な実装

    仕様が候補勧告段階に達すると、 非実験的な実装が可能になり、実装者は、 仕様に従って正しく実装されていることを実証できる任意の CR レベルの機能について、 接頭辞なしの実装をリリースすることが推奨されます。

    実装間で CSS の相互運用性を確立し維持するため、 CSS ワーキンググループは、非実験的な CSS レンダラーが CSS 機能の接頭辞なし実装をリリースする前に、 実装報告書（および必要な場合、その実装報告書で使用した テストケース）を W3C に提出することを求めています。 W3C に提出されたテストケースは、CSS ワーキンググループによるレビューおよび修正の対象となります。

    テストケースおよび実装報告書の提出に関する詳細情報は、 CSS ワーキンググループの Web サイト https://www.w3.org/Style/CSS/Test/ で確認できます。 質問は public-css-testsuite@w3.org メーリングリストに送ってください。
