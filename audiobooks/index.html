1. はじめに

この節は非規範的です。

オーディオブックは、読み上げ順序、メタデータ、および リソースによってまとめられた音声リソースの集合であり、そのすべてがマニフェストに含まれます。このオーディオブックはオープン Web プラットフォーム上に存在することも、 パッケージ化された実体として存在することもできます。

この仕様は、Web 上および企業間におけるオーディオブックの配布モデルを標準化することを目的としています。オーディオブックを利用するための さまざまなユーザーエージェントアーキテクチャを促進するものです。 主な目的は、現在標準によるサポートが十分でない出版業界の一分野を明確化すると同時に、 オーディオブックをオープン Web プラットフォームおよび新しいユーザーエージェントに開放することです。この仕様では、 コンテンツ作成者が使用すべきファイルタイプや形式については規定せず、それらを配信するためのマニフェスト形式のみを 規定します。

この仕様では、ユーザーエージェントがオーディオブックをどのようにレンダリングすることが期待されるかは定義しません。 ユーザーの読書体験を向上させるためにユーザーエージェントが提供できるアフォーダンスの種類に関する詳細は、 代わりに [pwp-ucr] で定義されています。

2. 用語

出版業界に固有の意味を持つ用語は、この文書では大文字で表記されます（例: 「Reading System」）。これらの用語と 定義の完全な一覧は [pub-manifest] に示されています。

各節では、用語の最初の出現箇所のみがその定義にリンクされています。

さらに、この仕様で使用するために、次の用語を定義します:

補足コンテンツ

補足コンテンツとは、オーディオブックのコンテンツに関連するものの、 出版物を完全に体験するためには必要とされないあらゆるコンテンツです。補足コンテンツの例には、写真、 図表、またはオーディオブックで言及されているトピックに関連するデータなどがあります。

3. 適合性

非規範的と明記された節に加えて、この仕様に含まれるすべてのオーサリングガイドライン、図、例、および注記は 非規範的です。この仕様のその他すべての内容は規範的です。

この文書におけるキーワード MAY、MUST、MUST NOT、RECOMMENDED、REQUIRED、および SHOULD は、ここに示すようにすべて大文字で表記されている場合に限り、BCP 14 [RFC2119] [RFC8174] に記載されているとおりに解釈されるものと します。

4. 構成

4.1 主要エントリーページ

主要エントリーページは、オーディオブックの推奨される開始リソースを表し、 そのマニフェストを発見できるようにする HTML リソースです。通常はオーディオブックを紹介し、 コンテンツへのアクセスを提供します。

主要エントリーページは、マニフェストへのリンクを含めるか、またはマニフェストを埋め込まなければなりません [pub-manifest]。また、目次を 含めるべきです。

オーディオブックは、パッケージ化によってマニフェストを別の方法で 発見できる場合を除き、主要エントリーページを含めなければなりません。存在する場合、そのページは リソースリストに含めなければなりません。

4.2 目次

目次は、オーディオブックの主要な節およびそれに含まれる可能性のある補足コンテンツの構造的な概要を反映した、 リンクの階層的な一覧を提供します。

目次は、いずれかのリソース内の [html] 要素（通常は nav 要素）によって 表現されます。この要素は、role 属性の値 [html] "doc-toc" [dpub-aria-1.0] によって識別されなければなりません。

目次が主要エントリーページに配置されている場合、目次は文書ツリー順 [dom] で、その role 値を持つ文書内の最初の要素でなければなりません 。それ以外の場合、マニフェストはその構造を含むリソースを 識別するべきです。

目次が主要エントリーページに配置されていない場合、 マニフェストはその構造を含むリソースを識別するべきです。

オーディオブックに追加のリソース（すなわち、補足コンテンツ）が含まれる場合:

  • 目次を含めるべきです。

  • 目次には、リソースへのリンクを含めるべきです。また、

  • すべてのリンクは出版物 リソースを参照するべきです [pub-manifest]。

注記

補足コンテンツを含める場合、目次からリンクされていなければ、ユーザーがこの コンテンツにアクセスできない可能性があることに注意してください。デフォルトの読み上げ順序に含まれないすべてのコンテンツへの リンクを提供することを強く推奨します。

注記

目次の構造と書式に関する詳しいガイダンスについては、出版物マニフェスト - 機械処理可能な目次 [pub-manifest] を参照してください。

5. マニフェスト

5.1 はじめに

この節は非規範的です。

オーディオブックのマニフェストは、ユーザー エージェントがオーディオブックを処理およびレンダリングするために必要とする基本情報を記述する一連のプロパティによって定義されます。これらのプロパティは、 Publication Manifest [pub-manifest] で分類されています。これらのプロパティが Publication Manifest から拡張される場合については、この節で規定します。

注記

オーディオブックのマニフェストは、[json-ld11] の特定の「形状」として定義されています。 この形状は、この仕様で定義される制約を表現する JSON スキーマ [json-schema] を通じても 非形式的に定義されています。このスキーマは https://www.w3.org/ns/pub-schema/audiobooks/ で保守されています。

5.2 要件

オーディオブックのプロパティおよびリソース関係を表現するための要件は、 次のように定義されます:

注記

プロパティの一覧では、[schema.org] および [pub-manifest] に記載されている各プロパティの正式名称を使用します。これらのプロパティの目的が 不明確な場合には、説明用のラベルを括弧内に示します。

必須:
  • conformsTo
  • @context
  • readingOrder
  • name (出版物のタイトル)
推奨:
  • abridged
  • accessibilityFeature
  • accessibilityHazard
  • accessibilitySummary
  • accessMode
  • accessModeSufficient
  • author
  • cover
  • duration
  • dateModified
  • datePublished
  • id (正規識別子)
  • inLanguage (出版物の言語)
  • readBy
  • readingProgression
  • resources
  • type
  • url (アドレス)
注記

一部のプロパティは、明示的に記述されていない場合には代替 情報から構成されるため、暗黙的に必須です。詳細については、内部 表現データモデル [pub-manifest] を参照してください （オーディオブック表現で異なるのは、type 用語のデフォルト値だけです）。

5.3 マニフェストのコンテキスト

オーディオブックのマニフェストは、JSON-LD コンテキスト [json-ld] を設定することから開始する必要があります。 コンテキストには、次の2つの主要な構成要素があります:

  • [schema.org] コンテキスト: https://schema.org
  • 出版物コンテキスト: https://www.w3.org/ns/pub-context
例 1 : コンテキスト宣言。 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    …
}

マニフェストのメタデータにグローバルな言語と方向を追加するために、言語と方向の 宣言 [pub-manifest] をコンテキストに追加することもできます:

例 2 : マニフェストのデフォルト言語としてフランス語を宣言する 
{
    "@context" : [
        "https://schema.org",
        "https://www.w3.org/ns/pub-context",
        {"language":"fr"}
    ]
    …
}

5.4 出版物の適合性

conformsTo 用語 [pub-manifest] で表現される適合性 URL は、 「https://www.w3.org/TR/audiobooks/」でなければなりません。

例 3 : 出版物の適合性をオーディオブックに設定する。 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/"
    …
}

5.5 出版物の種類

出版物の種類は、type 用語 [pub-manifest] を使用して定義されます。

例 4 : 出版物の種類をオーディオブックに設定する。 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "type"     : "Audiobook"
		…
}

type が指定されていない場合、Audiobook [schema.org] が デフォルトであると 見なされます。

5.6 プロパティ

5.6.1 作成者

作成者とは、 オーディオブックの作成を担当する個人または実体です。Audiobooks プロファイルでは、[pub-manifest] で定義されている作成者の完全な一覧を使用できます。

作成者の一覧には、オーディオブックについて推奨される2種類の作成者が含まれます:

  • author
  • readBy
例 5 : 書籍の著者 
{
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "@context" : ["https://schema.org","https://www.w3.org/ns/pub-context"],
    "type" : "Audiobook",
    …
    "url" : "https://publisher.example.org/janeeyre",
    "author" : {
        "type" : "Person",
        "name" : "Charlotte Bronte"
    }
}
例 6 : オーディオブックの著者とナレーター 
{
    "conformsTo" : "https://www.w3.org/TR/audiobooks/";
    "@context": ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    …
    "url"	: "https://publisher.example.org/janeeyre",
    "author" : {
        "type": "Person",
        "name": "Charlotte Bronte"
    }
    "readBy" : {
        "type": "Person",
        "name": "Ivan Herman",
        "id"	: "https://www.w3.org/People/Ivan/"
    }
}

5.6.2 再生時間

再生時間とは、オーディオブック内の音声リソースの長さです。 duration プロパティは、Publication Manifest [pub-manifest] で完全に定義されています。

再生時間は、マニフェストの一部としてオーディオブック全体について表現するべきであり、 デフォルトの読み上げ順序の項目レベルにも存在するべきです。

コンテンツ作成者が、オーディオブックの再生時間と デフォルトの読み上げ順序内の項目レベルの再生時間の両方を指定する場合、リソースレベルの再生時間は、 読み上げ順序内の項目の再生時間の合計と等しくなるべきです。

例 7 : 秒単位で表したオーディオブックの再生時間 
{
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "@context" : ["https://schema.org","https://www.w3.org/ns/pub-context"],
    …
    "url" : "https://publisher.example.org/janeeyre",
    "author" : {
         "type"  : "Person",
         "name"  : "Charlotte Bronte"
    },
    "duration" : "PT12345.235S"
}

5.7 デフォルトの読み上げ順序

デフォルトの読み上げ順序 [pub-manifest] は、 オーディオブック内の音声リソースをたどる特定の進行順序です。

デフォルトの読み上げ順序には、少なくとも1つの音声リソースを含めなければならず、 これは LinkedResource の type によって識別してもよい [pub-manifest]。デフォルトの読み上げ順序には 音声以外のリソースを含めてはなりません。

音声リソースは、URL [url] を介して全体を参照することも、 複数の章が1つのファイルに含まれるコンテンツの場合には、メディア フラグメント [media-frags] を使用して正確な開始点と 終了点を特定することもできます。

注記

リソースは読み上げ順序内で複数回参照できないことに注意することが重要です。 1つの音声ファイルが書籍の複数の章または 節の内容を表す場合には、目次を使用して、 より大きな音声ファイル内におけるそれらの章の開始点と終了点を指定できます。これはこの例で示されています。

注記

注釈でも、メディアフラグメントを使用してリソース内の注釈の位置を特定でき、 Web Annotations モデルと互換性があります。この方法は、 パッケージ化されていないオーディオブックのマニフェストにのみ適用されます。

例 8 : 単一リソースのオーディオブック読み上げ順序 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "url" : "https://publisher.example.org/janeeyre",
    "name" : "Jane Eyre",
    "readingOrder" : [{
        "type" : "LinkedResource",
        "url" : "audio/janeeyre.mp3",
        "encodingFormat" : "audio/mp3",
        "name" : "Jane Eyre",
        "duration" : "PT124503.123S"
    }]
}
例 9 : メディアフラグメントを使用した複数リソースのオーディオブック読み上げ 順序 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "url" : "https://publisher.example.org/janeeyre",
    "name" : "Jane Eyre",
    "readingOrder" : [{
        "type": "LinkedResource",
        "url" : "audio/part001.wav#t=0,457.931",
        "encodingFormat" : "audio/vnd-wav",
        "name" : "Chapter 1",
        "duration" : "PT457.931S"
    }, {
        "type" : "LinkedResource",
        "url" : "audio/part002.wav#t=12.741",
        "encodingFormat" : "audio/vnd-wav",
        "name" : "Chapter 2",
        "duration" : "PT234.245S"
    }]
}

5.8 リソースリスト

リソースリストは、 オーディオブックの処理およびレンダリングで使用され、読み上げ順序には列挙されていない追加リソースを列挙します。これは resources プロパティを使用して表現されます。

オーディオブックに補足コンテンツが含まれる場合、そのコンテンツは リソースリストで参照されなければなりません。

例 10 : 補足コンテンツを含むオーディオブック 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "url" : "https://publisher.example.org/janeeyre",
    "name" : "Jane Eyre",
    "resources" : [
        "cover.jpg",
        "portrait_CB.jpg",
        "supplement.pdf"
    ]
}

5.9 オーディオブックのプレビュー

プレビューは、オーディオブック全体を購入または ダウンロードする前に、完全なコンテンツをユーザーに体験してもらうための一般的な方法です。

プレビューは、[pub-manifest] で定義されている preview リンク関係を使用して識別されます。

プレビューは、外部に配置しても、オーディオブックのリソースとして含めてもかまいません。

例 11 : 外部プレビューを含むオーディオブック 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "url"	: "https://publisher.example.org/janeeyre",
    "name" : "Jane Eyre",
    "resources" : [{
        "type" : "LinkedResource",
        "url" : "https://publisher.example.org/jane-eyre-preview.wav",
        "encodingFormat" : "audio/wav",
        "rel" : "preview"
    }]
}
例 12 : 内部プレビューを含むオーディオブック 
{
    "@context" : ["https://schema.org", "https://www.w3.org/ns/pub-context"],
    "conformsTo" : "https://www.w3.org/TR/audiobooks/",
    "url"	: "https://publisher.example.org/janeeyre",
    "name" : "Jane Eyre",
    "resources" : [{
        "type" : "LinkedResource",
        "url"	: "preview.wav",
        "encodingFormat" : "audio/wav",
        "rel"	: "preview"
    }]
}

この節は非規範的です。

オーディオブックは、Lightweight Packaging Format [lpf] 注記に記載されている方法を使用してパッケージ化されます。

5.11 アクセシビリティ

この節は非規範的です。

オーディオブックの歴史は、アクセシビリティの世界に根ざしています。純粋な音声のみの出版物と、 テキストと音声の再生を同期する出版物の両方が、別の読み方を必要とする、または好むユーザーを支援するために 長年使用されてきました。

出版物におけるアクセシブルな同期メディアへのアプローチは、現在 Synchronized Multimedia for Publications Community Group によって進められています。そのような コンテンツを作成してオーディオブックに組み込む方法の詳細については、そのグループの成果を参照してください。

あるいは、コンテンツ作成者は、同等のテキストを HTML [html] リソースとして リソースに提供できます。

6. マニフェストの処理

この節は Infra Standard [infra] に依存します。

この仕様では、Publication Manifest の処理 アルゴリズム [pub-manifest] を次のように拡張します:

内部表現の生成

オーディオブックのマニフェストには、次の拡張 手順が追加されます:

  1. (§ 5.6.2 再生時間) 出版物の再生時間を次のように確認します:

    1. resourceDuration に個々の リソースの合計再生時間を保持させます。

    2. data["readingOrder"] の各 resource について反復します:

      1. resource["duration"] が定義されていない場合、検証 エラー。

      2. それ以外の場合、resource["duration"] があれば、 resource["duration"] を resourceDuration に加算します。

    3. data["duration"] が設定されていないため値を比較できない場合、 検証 エラー。

      それ以外の場合、resourceDuration が data["duration"] と同じ合計 再生時間を指定していなければ、検証 エラー。

    説明

    この手順では、読み上げ順序内のすべてのリソースが再生時間を指定していることと、 それらすべての再生時間の合計が出版物の合計再生時間と一致することの両方を確認します。

    各リソースの確認中に検証エラーが出されるのは、そのリソースが 再生時間を指定していない場合のみです。再生時間の 妥当性 [pub-manifest] は、Publication Manifest の アルゴリズムですでに確認されるため、繰り返す必要はありません。

データ検証

オーディオブックのマニフェストには、次の拡張 手順が追加されます:

  1. (§ 5.7 デフォルトの読み上げ順序) 読み上げ順序を次のように確認します:

    1. data["readingOrder"] が設定されていない場合、致命的 エラー。

    2. data["readingOrder"] 内の各 resource について反復し、resource が音声リソースでない場合、検証 エラーとし、resource を data["readingOrder"] から削除します。

    3. data["readingOrder"] が空のリストである場合、致命的 エラー。

    説明

    この手順では、音声リソースのみが読み上げ順序に列挙されることを保証し、 音声リソースでないものを削除します。

    各リソースを確認した後に読み上げ順序に項目が残っていない場合、 その出版物は有効なオーディオブックではないため、致命的エラーが返されます。

  2. (§ 5.5 出版物の 種類) data["type"] が設定されていないか、空のリストである場合、検証 エラーとし、« "Audiobook" » に設定します。

    説明

    この手順では、type プロパティが指定されていない場合に、 出版物のデフォルトの種類を Audiobook に設定します。

  3. (§ 5.2 要件) 次の各プロパティが設定されていることを確認します。設定されていない場合は、 それぞれについて検証 エラーを発行します。

    • data["abridged"]
    • data["accessMode"]
    • data["accessModeSufficient"]
    • data["accessibilityFeature"]
    • data["accessibilityHazard"]
    • data["accessibilitySummary"]
    • data["author"]
    • data["dateModified"]
    • data["datePublished"]
    • data["id"]
    • data["inLanguage"]
    • data["name"]
    • data["readBy"]
    • data["readingProgression"]
    • data["resources"]
    • data["url"]
    説明

    この手順では、推奨されるすべてのプロパティが設定されていることを確認します。これらの詳細については、 § 5.2 要件を参照してください。

  4. (§ 5.2 要件) data["readingOrder"] または data["resources"] 内のどのリソースにも、関係 cover を含む rel エントリがない場合、検証 エラー。

    説明

    この手順では、読み上げ順序とリソースリストを確認して、表紙が 指定されていることを検証します（すなわち、あるリソースの rel プロパティに値 cover があること）。

7. 機械処理可能な目次のユーザー エージェントによる処理

この節は非規範的です。

この仕様では、機械処理可能な目次 [pub-manifest] のための Publication Manifest のユーザーエージェント処理アルゴリズムを拡張して、目次 要素を次のように特定します:

  1. 主要エントリーページが利用可能な場合は、主要エントリーページ上で 目次要素を特定するアルゴリズムを実行します。
  2. 前の手順が成功しなかった場合は、[pub-manifest] の § 4.8.1.3 目次に記載されているように、利用可能であればマニフェスト内の関連リソースを特定し、 そのリソースに対して同じアルゴリズムを実行します。

詳細については、§ 4.2 目次も 参照してください。

8. セキュリティとプライバシーに関する 考慮事項

Audiobooks は Publication Manifest [pub-manifest] のプロファイルであるため、その仕様で詳述されているすべてのセキュリティとプライバシーに関する考慮事項が このプロファイルに適用されます。

このプロファイルでは、次の考慮事項を認識しています:

  • 読み上げ順序およびリソースリスト内の参照は、リモートとローカルの両方の リソースを参照できます。

9. オーディオブックに対するユーザーエージェントの振る舞い

この節は非規範的です。

この節では、オーディオブックを実装する際に期待されるユーザーエージェントの振る舞いについて概説します。処理 命令については、ユーザーエージェントは Publication Manifest [pub-manifest] 仕様のマニフェストの 処理節を参照し、 そこに記載されているすべての振る舞いに適合する必要があります。

この節で説明するユーザーエージェントのすべての振る舞いは、実装者に指針を提供することを目的としており、 厳格な要件ではありません。この文書の振る舞いは、主としてワーキンググループが公開したユースケースと要件 [pwp-ucr] 注記に基づいています。

9.1 オーディオブックのコンテンツを開いて ナビゲートする

ユーザーエージェントがオーディオブックを開き、マニフェストが Publication Manifest [pub-manifest] に定められた規則に従って処理された場合、そのオーディオブックはユーザー エージェントによって開かれるべきです。読み上げ順序、または利用可能な場合には目次にユーザーがアクセスできるようにすべきです。ユーザーエージェントは、要求されたときに ユーザーが利用可能なオーディオブックのコンテンツ一覧を提供できるべきです。音声以外の リソースが読み上げ順序に存在する場合、ユーザーエージェントはそれをユーザーに提示するか、 スキップするかを選択できます。

ユーザーエージェントは、読み上げ順序および リソースリスト内の音声以外のリソースをレンダリングする手段を提供すべきです。コンテンツをユーザーエージェントでレンダリングできない場合は、コンテンツが存在するもののレンダリングできないことを ユーザーに通知することが推奨されます。

主要エントリーページは、利用可能な場合、オーディオブックへのエントリーポイントとなることを 意図しています。コンテンツ作成者が主要エントリーページを提供しており、ユーザーエージェントが HTML コンテンツをレンダリングまたは処理できる場合、それを最初にユーザーへ提示すべきです。 主要エントリーページには目次が含まれる場合と含まれない場合があります。role="doc-toc" を使用して含められている場合、それを目次として扱うべきです。目次が 別の文書である場合、上記の要件を満たす限り、ユーザーエージェントが選択する任意の方法でレンダリングできます。主要エントリーページ またはその他の場所に目次が含まれていない場合、ユーザーエージェントは読み上げ順序を参照すべきです。

9.2 オーディオブックの再生可能性

ユースケースと要件 [pwp-ucr] 注記で概説されているように、オーディオブックは ユーザーエージェント内でナビゲート可能でなければなりません。つまり、ユーザーエージェントは、読み上げ順序をシームレスに移動するか、目次にアクセスすることによって、ユーザーがオーディオブック内を直線的または非直線的に 移動するための方法を提供しなければなりません。ユーザーエージェントはまた、ユーザーが個々の 音声ファイル内を短い時間単位で移動できるようにすべきです。

オーディオブックについて、ユーザーエージェントは、ユーザーが オーディオブックをナビゲート、再生、または一時停止できるプレーヤー インターフェイス [pwp-ucr] を提供すべきです。このインターフェイスは任意の 方法（すなわち、物理ボタン、視覚的インターフェイス、キーボード入力、または音声コマンド）でユーザーに提示できますが、 リスニング体験のどの時点でもアクセス可能であるべきです。

9.3 オーディオブックのパッケージ化と オフライン化

ユースケースと要件 [pwp-ucr] 注記では、 コンテンツをオフラインで利用できること、およびパッケージ化形式が 出版物の各反復に影響を与えないことを推奨しています。つまり、複数の ユーザーエージェントを介してコンテンツが多数のユーザーへ何度コピーされたとしても、中核となるマニフェストとその識別子は決して変更されません。

この仕様では、オーディオブックコンテンツのパッケージ化に Lightweight Packaging Format [lpf] を推奨しますが、 これは要件ではありません。オーディオブックのユーザーエージェントは、再生のために LPF ファイルを取り込むことができ、 この文書の要件と推奨事項に従ってコンテンツを表示すべきです。

ユーザーエージェントが自身のサービスから直接コンテンツを提供している場合（すなわち、小売業者またはコンテンツの リポジトリとして）、コンテンツをオフライン化またはダウンロードする方法を ユーザーに提供することが推奨されます。これは任意の形式を選択できますが、オーディオブックは完全かつ有効であるべきであり、 マニフェストに列挙されたコンテンツはすべて完全な形で提供されるべきです。ユーザーエージェントが 特定のリソース（すなわち、画像ファイルやデータ表）の表示をサポートしていない場合でも、 そのリソースはユーザーがダウンロードできるようにすべきです。

この仕様では、コンテンツ作成者が自身の コンテンツを保護したり透かしを入れたりする方法は提供しません。これは、現在すでに市場で利用可能な方法が存在するためです。コンテンツの配布を保護または制限したい コンテンツ作成者と連携するユーザーエージェントは、その要件に最も適した方法を 選択できます。

9.4 オーディオブックのアクセシビリティ

この仕様では、コンテンツ作成者が完全にアクセシブルなオーディオブックを作成するための方法を推奨し、提供します。ユーザーエージェントは、 アクセシビリティに関する節のこの情報を使用して、アクセシブルなオーディオブックインターフェイスを実装すべきです。 ユーザーエージェントは、アクセシブルなプレーヤーインターフェイスに加え、 alternate コンテンツを提供したコンテンツ作成者が、そのコンテンツを表示できるようにする方法を提供することが推奨されます。
